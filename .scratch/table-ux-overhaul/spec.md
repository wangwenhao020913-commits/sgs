# 桌面交互与询问流重构（table-ux-overhaul）

Answer contract: on

**一句话**：把玩家实机报障的 13 个问题（初始化抢跑 / 卡顿 / 预发动 / 提示区 / 转化目标 / 无懈 / 档位 / 跳过策略 / 标记刷新 / 多选座位 / 手牌直选）收敛成四条主线——
**合法性只有一处算（服务端算、前端只读）**、**"要不要问"只有一个策略位**、**交互面只有一个真源**、
**派生通道按时序游标增量**——并按五批十四票落。

**签认**：用户 2026-11-11 逐条裁定（本文件 §2 是唯一裁定记录，票面不再逐条"待签"）。

### 注①：为什么"重录"必须与行为改动落在同一个提交

`.githooks/pre-commit` 在 `src/`、`tests/` 改动时跑**全量**门禁，而
`tests/test_replays.py::test_golden_replay_matches_byte_for_byte` 是"**真重跑引擎** + 逐字节比对"。
只要金录像红，hook 就**拒绝提交**——所以"先改行为、最后统一重录"的排法不成立：
中间那次提交根本进不去。

由此定下三条落地口径：

1. **02 只落管道、不接线**：策略位 / 会话配置 / 侧车 meta / `respond_candidates` 预筛口全部就位，
   但**没有任何窗口消费它** ⇒ 记录流零变化，基准零重录。
2. **05 接窗口，但引擎缺省 OFF、网页会话缺省 ON**（Q4(a)）⇒ 引擎层（金录像 / `batch_games` /
   `ai_eval` / 旧录像回放）行为逐字节不变；玩家在网页里立刻看到"没有无懈的人不被问"。
3. **只有 04 需要重录**，且在与 04 的实现**同一个提交**里完成；06 只做账本 / ADR / GLOSSARY 收口。

## §4 金录像策略（用户 2026-11-11）

- **金录像 = 冻结的行为契约**：行为**有意**变更时**必须重录**，不是"不许变"。
- 重录准入：票面列"重录清单"（哪条基准 / 哪条记录 / 变什么 / 为什么），`goals.py` 的**机制断言**保持不变（重录只换字节，不换"这条基准在证什么"）。
- 冻结表（`tests/test_replays.py` 的 `STANDARD_108_REPLAY_BYTES`）与 `tests/replays/README.md` 索引一并更新。
- 重录面（按 §3 注① 的口径）：`tests/replays/*.jsonl` 共 60 条；含 `SKILL_ACTIVATION` 19 条、
  含无懈窗口 45 条、含 DODGE 窗口 59 条、含 PEACH 窗口 60 条。
  **只有票 04（档位拆面）会动它们**（派发面按档拆 + 需要牌逐档问）；实测 60 条里
  **0 条**含【八卦阵】发动、**1 条**含【护驾】，故需要牌侧预计只碰 1–2 条。
  票 02 / 05 在"引擎缺省 OFF"下**零重录**（网页会话的行为变化没有基准覆盖，也不需要）。

## §5 验收总则

- 每票的 `## Answer` 必须写：改动摘要 / 会红的既有断言 / 新增断言清单 / 门禁结果。
- 新增断言必须落在**真实产出路径**上（`CODING_STANDARDS.md` §6），不许只测合成载荷。
- 前端行为变更必须过 `bash tests/smoke-web.sh`；改 DOM API 形状的票还要走 `bsk` 实机（`docs/agents/acceptance-web.md`）。
- 提及新机制 / 新动作面 / 新信息通道的票，先过 `docs/agents/ai-adaptation.md` §1 checklist，并更新 `tests/test_ai_adaptation.py` 的登记表。
- 全量门禁 = `bash tests/run_all.sh`（≈8 分钟，后台跑）。

## §6 不变量（改代码时不许破坏）

1. **候选 = 接受**：前端能点的每一样东西，都必须是服务端下发的候选/清单里的成员；前端不许自己推导规则合法性（`GLOSSARY.md`「合法行动集合」「候选索引」）。
2. **不升档**（规则集 §2.1.2.3）：档按"武将技 > 装备技 > 使用牌 > 流程操作"；实现方式是**按档迭代**，不是把档混在一张面里让玩家自己踩。
3. **记录流 = 权威事实**：显示层文案、悬浮提示、模板不得进入 `Query.prompt`（它在记录里）。
4. **派生通道只增 + 游标**：任何新的事件通道必须按 `after` 游标切窗口，不许全量扫描。
5. **前端不猜**：拿不到池就是"点不了"，不许兜底成"全都点得动"。

## §7 已知风险

| 风险 | 缓解 |
|---|---|
| 预览请求把预发动变成"每点一次一个往返" | 独立端点（不碰 `view()`）+ 去抖 80–120 ms + `answers_seq`/版本号丢弃过期响应；票 01 必须先落 |
| 拆档后询问条数变多、玩家嫌繁琐 | 档 0/1 用一击"是否发动/确认"（不是面），档 2 才铺候选面 |
| 重录覆盖 60 条基准 | 票 06 单列、逐条登记；机制断言不动 |
| 文案普查是大头工作量 | 票 07 先出 `prompts.json` 初稿（用户改字），实现不阻塞 |
| 前端文案模板与引擎 `Query.prompt` 漂移 | 只做**显示覆盖**：缺键退回 `Step.wording` → 引擎 `prompt`，三层兜底 |
