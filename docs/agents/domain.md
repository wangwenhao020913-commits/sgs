# 领域文档（Domain Docs）

工程类技能在探索代码库时应当如何消费本仓库的领域文档。

## 探索之前，先读这些

- **`开发文档/`**：本仓库的稳定态设计文档（01-总体设计、02-规则引擎设计、03-数据模型与技能描述、04-AI与交互设计、05-测试与验证策略、06-里程碑与风险）。改动某个区域前，先读对应那份。
- **`开发文档/06-里程碑与风险.md` 第 4 节「决策记录（ADR）」**：本仓库**当前**的 ADR 就地存放处，已登记 ADR-001～007（无懈可击响应窗口、拼点平点、转化杀属性、丈八蛇矛花色点数、技术栈、界限突破技能版本、游戏结束判定）。改动涉及这些决策覆盖的区域时，先读它们，**不要**静默覆盖。
- **`docs/adr/`**：仅在决策记录从上面那张表溢出、或某条决策需要长篇论证时才建立；建了之后以它为准。目前不存在。
- **`参考资料/`**：官方规则集研究、界标准包武将资料、虚拟牌与特殊使用规则研究——领域知识的**一手来源**，用于核对术语与裁定。
- **`GLOSSARY.md`**（仓库根目录，目前不存在）：项目术语表。见下“惰性创建”。

若上述文件不存在（如 `GLOSSARY.md`、`docs/adr/`），**静默继续**。不要指出它们缺失，也不要主动建议先创建。
`/domain-modeling` 技能（经 `/grill-with-docs` 触达）会在术语或决策真正被敲定时惰性创建它们。

## 文件结构

本仓库为单上下文（single-context）布局：

    /
    ├── AGENTS.md              ← 协作规则
    ├── GLOSSARY.md            ← 术语表（惰性创建）
    ├── docs/
    │   ├── agents/            ← 本目录：技能配置
    │   └── adr/               ← 长篇 ADR（暂无，决策当前在开发文档 06 第 4 节）
    ├── 开发文档/              ← 稳定态设计文档 + 当前 ADR 表
    ├── 参考资料/              ← 规则与武将一手资料
    └── tests/                 ← 文档/规则校验脚本

## 使用术语表的词汇

当你的产出命名一个领域概念时（工单标题、重构提案、假设、测试名），
使用 `GLOSSARY.md` 中定义的术语，不要漂移到术语表明确回避的同义词。

若需要的概念尚不在术语表中，这是一个信号：要么你在发明项目不使用的语言（重新考虑），
要么确实存在缺口（记录下来交给 `/domain-modeling`）。

术语以中文为准（杀、闪、桃、判定、濒死、时机、响应、结算栈等）。
代码标识符可用英文对应，但**一篇文档内只用一个名字**，且以术语表为唯一裁决处。

## 标记 ADR 冲突

若你的产出与既有 ADR 矛盾，显式暴露出来，而不是悄悄覆盖：

> _与 ADR-007（游戏结束判定：即时终止一切结算）冲突，但值得重新讨论，因为……_
