# 制作武将技能（Skill Authoring）

新增或修改一条**武将技能**时走这条流水线。它只解决一件事：把"每次重新推导"变成"读表 +
照表执行"，并且**把不确定的地方硬停下来**——歧义、缺口、拿不准的边界，一律不实现。

**仓外作者（还没 clone 过本仓 / 第一次给本仓提技能）先读 `docs/agents/diy-heroes.md`**：选路、装入口 skill、要改哪几个文件、跑什么门禁、版权边界都在那一份，本文件从"选完路之后"开始。

本文件是**过程与纪律**。事实分住四份子文档，本文件不复述它们：

| 子文档（`docs/agents/skill-authoring/`） | 回答什么 |
|---|---|
| `docs/agents/skill-authoring/readings.md` | 官方默认书写规范：一条技能文本该怎么读（区域 / 回合 / 指代 / 数值 / 触发粒度） |
| `docs/agents/skill-authoring/shapes.md` | 代码构造：这条技能该落成哪种形状；框架此刻有哪些原语（封闭集登记表） |
| `docs/agents/skill-authoring/edge-cases.md` | 极端情况：按形状分组的"必须回答的问题"清单 |
| `docs/agents/skill-authoring/batch-ticket.md` | 票面骨架：一将一票、DoD、门禁与提交节奏 |

这四份之外，还有四份**不是技能文档、但会改技能怎么写**的——命中对应形态时必须读：

| 文件 | 什么时候必须读 |
|---|---|
| `开发文档/04-AI与交互设计.md` §4（人类交互设计） | 动询问面 / 候选集合 / 预览。每步的可点集合由后端**现算**（`06`（§5「程序化约定与偏离一手」）的预览端点行）⇒ 声明里的 `step.pool`、`_seat_bounds`、options 回调会被**反复调用**，必须纯净、无副作用、可重入 |
| `开发文档/06-里程碑与风险.md` §5（程序化约定与偏离一手，含 §5.9） | 动作面约定、需要牌按档逐问、无懈只问合格者、询问跳过策略、**重录纪律**——账本行也在这个节 |
| `GLOSSARY.md` | 「需要牌档位」「只问合格者」「预发动」这些词的定义口径；读法与账本冲突时以账本为准 |
| `docs/agents/ai-adaptation.md`（§1 checklist + 三张登记表） | 票里带来新的机制 / 动作面 / 信息通道时，先过一遍 checklist；登记表漏登的症状常常不是红，而是"技能发动了、什么都没发生" |

工具（只读）：`tools/dump_catalog.py`（形状指纹与封闭集）、`tools/similar_skills.py`（相似技能反查）、
`tools/pool_census.py`（将池构成清单：**加武将 / 改池后先跑它**，一次列出「哪些断言写死了版本 /
真名 / 技能数 / 形态格」并逐站点对账；`--check` 不一致即非零退出，`--json` 机读）。

---

## 1. 什么时候用它

- 新增武将 / 新增技能（含"OL 增补"、觉醒后获得的 ☆ 技能）。
- 修改一条已有技能的读法或形状（改判、版本并存、口径纠正）。
- 评审他人提交的技能改动（同一套判据，反向用）。

不适用：纯数值/文案改错、与技能无关的引擎重构。

## 2. 六问流水线（逐技能跑一遍，产出写进票面）

| 步 | 问 | 动作 | 产出（缺一项不许进下一步） |
|---|---|---|---|
| 1 | 官方怎么写、怎么读 | 读牌面原文 + `readings.md` 的四类读法 | **读法表**（四类 + 触发粒度） |
| 2 | 这条技能做什么 | 拆六元组：时机 / 代价 / 目标池 / 效果 / 修饰值 / 触发次数 | 六元组一页 |
| 3 | 有没有同形的现成技能 | `tools/similar_skills.py --like <最像的>` 或按形状反查 | **候选 3 条**，写明抄哪一行 |
| 4 | 落成哪种形状 | 查 `shapes.md` 的形状表，选中**一行**；命不中 ⇒ 停（C1） | 形状名 + 样板 `文件:行` |
| 5 | UI 怎么显示 | 按 `shapes.md` 的「UI 触点」一节逐项过 | 触点清单（每项落到一个已存在的测试垫片） |
| 6 | 边界怎么办 | 按 `edge-cases.md` 逐条回答 | 边界断言列表（每条一个测试名） |

第 3、4 步**不许跳过**：跳过的代价是"另起一套机制"，那会让下一条技能更贵。

## 2.1 规范确认门（签了才动工）

**开工 = 写 `src/` 或 `tests/` 的第一个字节。** 六问的产出还不是许可：把这条技能的规范摆成
票面的一张表，**用户签了才写码**。一将一票，**整批一次签**；没签就写 = 返工。

票面 `### 询问剧本` 一问一行，四列缺一列不动工：

| 步 / 段 | 询问文本（**逐字**） | 实现方式 | 兜底 |
|---|---|---|---|
| 预发动第 1 步 | 「…」 | 牌面直选（套 `hero.sunquan.zhiheng`） | 无候选 ⇒ 该步不出现 |

1. **文本逐字**：每个**预发动步骤**、每一段**效果**都要有原文，并写明它落在哪个槽位——
   `SkillDef.requirement`（一句话）/ `SkillDef.step_requirements`（逐步）/
   `options.js:OPTION_LABELS`（多选项标签）。读不到的形态必须标出来（单选项提交态读不到
   标签，见 `edge-cases.md` O4）。写"待定"= 没填。
2. **实现方式**：从 `shapes.md` §4.1 的闭集里选**一行**，再写"套不套用现成模板"——第 3 步的
   相似技能候选就是模板源：套用写它的 id，不套用写一句为什么。闭集之外 = **C3 停**。

3. **兜底**：每一步都写"没有合法应答时怎么办"（`edge-cases.md` §3.1 的兜底行），每条带断言。
   **死路不算兜底**：文案让玩家点哪个控件，那个控件就得亮着且点得动。

**签字顺序**：先把整张 `### 询问剧本` 写出来、**再**问口径。用户对口径的逐条回答落在票面 §0，
算对 §0 的签字；整张表仍要一句「同意」才动工。账本行（`06`（§5「程序化约定与偏离一手」））的**措辞**不随裁定自动生效——
收口时把行文一并交签，或明确授权实现者按裁定的措辞写入。

## 3. 批次纪律（提速的全部秘密）

| 事项 | 纪律 |
|---|---|
| 票的单位 | **一个武将 = 一批 = 一张票**（该武将的全部技能一起做） |
| 迭代期 | 只跑相关单文件（`tests/test_hero_<包>.py`）+ `bash tests/smoke-web.sh`（实测 60–70 s）+ `bash tools/check_goldens.sh`（秒级）。**不提交** |
| 收口 | 批次全部技能落地后**提交**：全量门禁由 pre-commit hook 跑（本机实测 ≈8 分钟），失败拒绝提交、工作树不动。手工跑全量只在"不提交、先看红/绿"时 |
| 提交 | **一次** commit。`wip:` 分档（用户 2026-11-12 裁定）：预计 **≤30 分钟**的票不做 `wip:`；预计 **>30 分钟**或机器中断风险高时，过半落一个 `wip:`（交付前 squash / amend 掉）——但每个 `wip:` 也要付一次全量 hook（≈8 分钟），别把它当免费检查点 |
| 实机验收 | 只有"新增询问形态 / 改了 DOM 形状"才走真实浏览器（`docs/agents/acceptance-web.md`）；其余用 `tests/support/ui_smoke.mjs` 的合成载荷覆盖 |
| DoD | 批内每条技能二选一：**已实现**（带能红的回归）或**已摘出**（附裁定票链接）。不许"做了一半" |

## 3.1 多将一批（用户 2026-11-02 裁定：一次给 N 个武将时走这条）

**一将一票不变、一将一提交不变**；变的只有"分析"和"签字"两段的组织方式。

| 段 | 做法 |
|---|---|
| 分析（**并行**） | 每个武将起一个**只读**子代理：读 `readings.md` / `shapes.md` / `edge-cases.md`，跑 `similar_skills.py --like` + `dump_catalog.py --hook`，产出**自己那张票**的六问 + `### 询问剧本`；只写 `.scratch/<effort>/issues/NN-<slug>.md`，**不碰** `src/` / `tests/`，不交码 |
| 签字（**一轮**） | N 张询问剧本表一次交给用户；一句「同意」= N 票同时过门，各票票头分别写 `规范确认: 已签（日期；多将一批一次签）` |
| 实现（**串行**） | 两将的 `Touches:` 必然重叠（`src/sgs/agents/heuristic.py`、`tools/sgs_web/descriptions.json`、`tools/sgs_web/static/options.js`、`test_hero_catalog.py`、`test_hero_dealing.py`、`test_web.py`、`test_heuristic_ai.py`、`test_ai_cases.py`、`tests/test_all_ai_games.py`、`tests/support/ui_smoke.mjs`、`开发文档/06`）⇒ **不并行实现**；按票顺序做，默认池计数**逐票 +1**（每改完一票跑一次 `tools/pool_census.py --check`，别一次 +N） |
| 门禁 | 迭代期逐票三件（单文件 + `smoke-web` + `check_goldens`）；提交时 hook 的全量**照旧每票一次** |

两条前置，缺一条就别起并行分析：

- **派发子代理之前先提交**（或先明确告知它"当前工作树未提交"）——见 `AGENTS.md` 注意事项 3。
  本仓已发生过两次子代理把别人的活打回 HEAD。
- **父代理核 diff、再独立跑一遍门禁**：子代理交回的表不是落地结果，`src/` / `tests/` 一律由
  父代理串行改（派发纪律见 `docs/agents/issue-tracker.md` 那一节）。

另外两条（同一次裁定）：

- **不做多将一提交**：那会把 `E1` 金录像变红变成无法归因。
- 分析子代理只交表：读不到的形态照样标出来（§2.1 第 1 条），不许猜；各表里的硬停项各自开裁定票。

## 4. 硬停判据（命中任一条，立即停）

"绝对不要模棱两可"的落地方式：**不确定不是凭感觉，而是命中下面某一条**。命中就停，不实现、
不记账、不写测试。

| 编号 | 触发条件 |
|---|---|
| **A1** | 一手文本存在**影响结算**的平台差异（OL / 移动版 / 台服），且账本没有对应行 |
| **A2** | 牌面出现已裁定词（任意张 / 至多 / 其中 / 这些 / 区域 / 一张 / 1 点 / 一名角色 / 其他角色 / 另一名其他角色），而 `06`（§5「程序化约定与偏离一手」）没有对应行 |
| **A3** | 文本自相矛盾（前提限定 A，后句判 B） |
| **A4** | 标 / 界两版**同短 id 但文本不同**，而行为差异没有在声明里显式区分（会被分步文案表/短 id 表遮住） |
| **B1** | **触发粒度**判不出（"一张 / 1 点"与"无限定词"三者都不贴） |
| **B2** | 时机不在 `Timing` 枚举里、也不落在已登记的接缝上 |
| **B3** | 数值口径无账本行（基数 vs 最终值、是否叠加、与既有 +N 的先后） |
| **C1** | 五种原语（钩子 / 接缝 / 修饰器 / 流水线步骤 / 提供者）**组合也表达不了** ⇒ 架构缺口 |
| **C2** | 需要"第六种机制"或**按技能名特判**才能实现 |
| **C3** | 需要**新的询问形态 / 新的 DOM 形状**，而现有测试垫片里没有 |
| **D1** | 某条**边界行为**在任何一手来源里找不到、账本也没裁定（例：置入装备时目标同槽已占） |
| **E1** | 金录像变红 ⇒ 停，**不得自行重录** |
| **E2** | 必须改共享原语，且改动落在"别人也在用"的路径上 ⇒ 先停下确认影响面 |

判据集**恰好是这 13 条**（`tests/test_skill_authoring_docs.py` 钉住）；增删要同时改测试，
防止悄悄放宽。

## 5. 停手要交什么

停手不等于说一句"我不确定"。产出是一张**裁定票**（`.scratch/<effort>/issues/NN-<slug>.md`，
`Status: open`），必含八项：

1. 牌面原文 + `三国杀详细规则.txt` 的章与行号；
2. 至少两种读法，各自一句话写明**结算后果**；
3. 一手证据（有则引 URL / 行号；没有就写"未找到"）；
4. 我的建议 + 理由；
5. 影响面：还会影响哪些技能、哪些既有断言；
6. 阻塞：本批哪条技能被摘出（其余技能**继续做**，见 `batch-ticket.md`）；
7. **不写实现、不写账本行**——账本由用户最终裁定；
8. 若属于 C1（架构缺口），写清"缺的是哪个原语、别的技能为什么也不能复用现有原语"。

## 6. 自身体检（每次开工先跑）

```bash
.venv/bin/pytest -q tests/test_skill_authoring_docs.py   # 文档与代码是否还同步
.venv/bin/python tools/dump_catalog.py --seams --points --steps   # 框架此刻的原语面
.venv/bin/python tools/pool_census.py --check          # 将池计数与四张登记表是否自洽（加武将后必跑）
bash tools/setup-dev.sh                                # 只在**新机器 / 换机器**首次跑：装 hook + 建 .venv + 换行口径
```

第一条红了 = 框架变了而文档没跟上，**先修文档再干活**。`pool_census.py --check` 非零退出 =
有写死的版本 / 真名 / 技能数 / 形态格没跟着这次加武将改（`huo-wolong-yanliang` 那批加 2 个武将，
首轮全量 12 条红里 9 条同源，就是它一次列出来的）。`setup-dev.sh` 不跑 = **门禁静默不跑**
（`core.hooksPath` 不随 clone 走）或金录像因 CRLF 整片变红，别把它当成"可选步骤"。

入口 skill 也由第一条一起核：它的仓内副本是 `skills/hero-skill/SKILL.md`（`判据版本` 行与 § 锚点
必须与本文档同进退；本机安装副本怎么装进 agent，见 `diy-heroes.md` 的「装 skill」表）。

## 7. 谁会更新这份文档

| 变化 | 谁改 | 怎么逼出来 |
|---|---|---|
| 新时机 / 新接缝 / 新修饰点 / 新询问种类 / 新帧型 / 新区域 / 新步骤类型 | 落地那张框架票 | 审计测试**反向核**：代码里每个成员都必须在 `shapes.md` 的登记表里有归属，漏登记即红 |
| 新机制（翻面 / 拼点 / 标记…） | 先 C1 停 → 架构缺口票 → 缺口落地那张票 | 落地后上一条自动接上；`Timing` 四轴计数由 `tests/test_timing.py` 对账 |
| 新 UI 形态（新询问弹窗、新交互面） | 落地那张 UI 票 | 审计测试核"UI 触点表"引用的符号在 `tools/sgs_web/static/*.js` 里存在 |
| 新**装载点 / 登记面**（声明级 `SkillDef.flow`、`register_activation`、`ACTIVATIONS` 这类"技能怎么被挂进引擎"的公共件） | 落地那张**框架**票 | 机械检查只覆盖"文档点名的 `文件:符号` 真的存在"（`tests/test_skill_authoring_docs.py`）；**"该不该有这一行"是判断题**，由评审的 Standards 轴 enforce——票 20 的 `SkillDef.flow` 就是漏在这里被评审抓到的 |
| 新账本裁定 | **用户** | 账本行由用户签；本流程只提案 |
| 本文件（`skill-authoring.md`）的**读单 / §6 自身体检 / §4 停手表**有改动 | 改这份文档的人 | 入口 skill `skills/hero-skill/SKILL.md` 的「判据版本」行与 § 锚点必须跟着动；`tests/test_skill_authoring_docs.py` 核（仓内那份缺席即红；本机安装副本的装法见 `diy-heroes.md` 的「装 skill」表） |

**skill 本身不碰框架层**：它只改业务层（技能声明 / 回调）与文档、提案账本；框架层改动走
独立的通用改动票（这就是 E2）。这条保证这套流程不会自己悄悄长出新机制。
