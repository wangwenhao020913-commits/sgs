# 极端情况清单（Edge Cases）

每条技能做第 6 问时过一遍这张清单：**命中哪条，就在票面写一句"本技能怎么办"，并给一个测试名**。
清单按"形状"分组——你选了哪种形状，就重点过那几组。

总纪律三条（适用于全部形状）：

1. **不发没有候选的询问**。没有可选项时，要么整条技能取消（零副作用），要么在**候选阶段**就
   不提供入口——绝不发一条玩家无法合法应答的询问。
2. **"可以不选"与"必须选但没得选"是两件事**。前者给 `Pass`；后者整条取消。
3. **每个效果都要问一句"这里会不会挂起"**。效果里只要搬牌，就可能内联触发别人的钩子；会挂起
   就要有帧内游标（重入既不重做也不漏做）。

## 1. 通用组（所有形状都过）

| # | 问题 | 本仓的默认处理 | 去哪看 |
|---|---|---|---|
| G1 | 付不起（没牌 / 没装备 / 没手牌） | 候选阶段就不产出；已发动则在成本步取消（零副作用） | `_zhiheng_offers` 一类 |
| G2 | 付得起但**没收益**（满血给桃、牌堆空、限定技浪费） | 一般仍允许（玩家可以浪费）；但**无效果的候选**要问一句"该不该出现" | 【替身】满体力可发动 |
| G3 | 数量语义：任意 / 至多 / 恰好 / 至少 | 任意 ⇒ `lo=1, hi=None`（不含 0）；至多 ⇒ 上限 + `Pass`；恰好 ⇒ `lo=hi` | `readings.md` |
| G4 | 触发粒度：限定词 | 一张 / 1 点 ⇒ 逐张逐点；无限定词 ⇒ 逐事件 | `readings.md` |
| G5 | 多目标：逐目标还是整次 | 牌面写「一名角色…后」⇒ 逐目标（游标推进）；写「使用…后」⇒ 整次 | 【铁骑】逐目标判定 |
| G6 | 转化牌 / 虚拟牌 | 产物牌型 vs 来源牌区；「使用/打出」不看区 | 账本「能直接选牌…」与虚拟牌研究 |
| G7 | 挂起续跑 | 每个"已付 / 已摸 / 已展示"都要帧内游标 | `_jie_jianxiong` 范式 |
| G8 | 同帧第二次触发 | "是否发动"的答案会被第一次复用（已裁定，不改） | `06`（§5「程序化约定与偏离一手」）F8 行 |
| G9 | 状态在途中翻转（目标死亡、体力变化让判据翻假） | 在飞帧要继续（把判据定格在帧私有） | 界【谦逊】/【救援】的在飞放行 |
| G10 | 收尾：死亡 / 平局 / 断牌堆 | 摸牌短摸即平局；死亡走终局清栈 | `tests/test_death.py` |

## 2. 按形状组

### 2.1 选牌类（`PickCards` / 手写 `ask_selection`）

| # | 问题 |
|---|---|
| C1 | 下限 0 允许吗？（本仓一律从 1 起；"0 张"不是合法动作） |
| C2 | 牌面写「手牌」还是「一张牌」？前者只手牌，后者手牌 + 装备 |
| C3 | 选自己的牌 ⇒ 牌面直选（`isOwnZonePick`），**不要**另铺面板 |
| C4 | 选项会影响候选面时（例：弃手牌 / 置装备），用 `exclude_cards` 可调用档收窄——**唯一判据** |
| C5 | 目标区域已有同位牌（同槽 / 同花色）时，是"可选但无事发生"还是"非法候选"？ |

### 2.2 选人类（`PickSeats`）

| # | 问题 |
|---|---|
| S1 | 含不含自己？（「一名角色」含、「其他角色」不含、「另一名其他角色」排除两个） |
| S2 | 可否选 0 名？（默认至少 1 名；"任意名"仍要 ≥1） |
| S3 | 目标池要不要按前序答案收窄？（`pool` 可调用档） |
| S4 | 池为空时整条取消，而不是发空询问 |

### 2.3 选项类（`PickOption`）

| # | 问题 |
|---|---|
| O1 | 某个选项此刻**不可能执行**（没手牌 / 目标没有空槽）⇒ 该选项不该出现（`options` 可调用档） |
| O2 | 选项闭集要不要 `Pass`？（"可以不选"才给） |
| O3 | 两个选项的**先后顺序**是否影响结算（"选择结束后摸一张"= 所选那项**结算完**才摸） |
| O4 | 选项的中文标签：单选项 + `Pass` 走"提交/放弃"，**读不到** `OPTION_LABELS` |

### 2.4 钩子类（`Hook`）

| # | 问题 |
|---|---|
| H1 | `per_point` 还是整次？（看牌面有没有「1 点」） |
| H2 | 条件要不要自校"持有者是我"？（不自校 = 任何人挨打都触发；`tests/test_hero_catalog.py` 有机械检查） |
| H3 | 触发时要不要问"是否发动"？（牌面有「可以」才问；锁定技不问） |
| H4 | 回调里能不能提问？（能，但要 `return "stay"` 并有续跑游标） |
| H5 | 同一时机上有别的技能时，顺序有没有依赖？ |

### 2.5 修饰器类（`Modifier`）

| # | 问题 |
|---|---|
| M1 | 改的是**主体侧**还是**客体侧**？（马术 vs 卧龙马） |
| M2 | 连续型（查询期算，失去即消失）还是一次性（落座位状态）？ |
| M3 | `None` 表示"无限制"的挂点（`COUNT_LIMIT` / `DISTANCE_LIMIT`），别把它当 0 |
| M4 | 与既有 +N 的叠加次序（本仓：数值只有加减、加在最终值上） |

### 2.6 放置 / 状态位类

| # | 问题 |
|---|---|
| P1 | 归还时机（回合末 / 永久 / 被使用后） |
| P2 | 可见性（公开 / 只自己 / 随牌面）——要在数据里显式声明三项 |
| P3 | 这些牌算不算手牌 / 手牌上限 / 场上的牌（本仓：都不算） |

## 3. 写进票面的形式

每条命中的边界写成一行：

```
- [G1] 手里没有装备牌 ⇒ 「置入装备」这一项不出现（`_jie_jieyin_options`）→ test_...occuped_slot
```

没命中的组写一句「第 2.3 组不适用（本技能没有选项步）」，**不许整组留空**——留空与"忘了想"
在评审时看不出来。

### 3.1 兜底行（**每个询问步骤**都要有一行）

「没有合法应答时怎么办」不许留空，也不许写"应该不会发生"。选一条默认，写清动作与断言：

| 情形 | 兜底动作 | 判据在哪 |
|---|---|---|
| 候选为空（付不起 / 池空 / 选项不可执行） | 候选阶段就不产出入口；已动工的在成本步取消（**零副作用**） | G1 / S4 / O1 |
| 玩家可以不选 | 给 `Pass`（"任意"不含 0 张；选牌一律从 1 起） | 总纪律 2 |
| 必答但只剩一条合法路 | **直提态**：单候选直接提交，不铺面 | `pending.js:directAction` |
| 隐藏面渲不出清单（读别人手牌） | **不翻** `preactivated`，走直提态 + 逐步问 | `shapes.md` §4 的预发动准入表 |
| 面不支持 / 规格缺失 | **fail-closed**：一句明话、不铺控件、不猜顺序 | `pending.js:renderUnsupported` |
| 效果里搬牌会触发别人的钩子 | 帧内游标：重入既不重做也不漏做 | G7 |

**死路不算兜底**：文案指向的控件必须真的可点。反面样板是票 23 报障——提示条写着「点技能
【…】进入预发动」，按钮却是灰的（两个写方各说一半）。所以兜底的判据不是"我写了兜底"，而是
**这一问在任何状态下都有下一步**：要么有可点控件，要么整条不出现。
