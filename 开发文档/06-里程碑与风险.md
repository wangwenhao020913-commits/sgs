# 06 里程碑与风险

---

## 1. 里程碑规划

### M0 规则与设计冻结（当前阶段）
- 交付：规则文档缺口补齐；本套开发文档；文档校验测试通过。
- 验收：`tests/run_all.sh` 全绿；规则存疑点全部登记为决策项。
- 产出物：`三国杀详细规则.txt` + `开发文档/`。

### M1 引擎骨架可跑通最小对局
- 范围：状态模型、时机枚举、结算栈、行动校验、脚本玩家。
- 内容：仅【杀】【闪】【桃】+ 无武将；无身份 1v1（2 人）；命令行。
- 验收：可完整打完一局；同种子结果一致；单元测试覆盖使用全步骤。
- 风险最高点：**结算栈与插入结算**是否正确。

### M2 标准版身份局
- 范围：108 张牌、判定、延时锦囊、无懈可击、濒死、死亡奖惩、
  身份胜负、4～8 人配置。
- 验收：Golden Replay 用例 ≥ 30 条；不变量 fuzz 无失败。
- 关键验证：无懈嵌套、目标时机、同时死亡判定。

### M3 标准版武将 + 启发式 AI
- 范围：12～15 名武将（覆盖各类时机）；随机 AI + 启发式 AI。
- 验收：一局 5 人全 AI 可无人干预跑完并给出正确胜负。
- 关键验证：技能时点（受 1 点伤害逐点触发等）。

### M4 可用界面 + 完整标准局
- 范围：极简 Web 界面、事件流渲染、询问应答、回放。
- 验收：人类可完整打完一局 8 人身份局；可回放复盘。

### M5 军争篇
- 范围：52 张牌、属性伤害、连环传导、【酒】、藤甲 / 白银狮子。
- 验收：属性与连环专项测试通过；AI 会使用 / 防范属性伤害。
- 注意：军争显著提高伤害上限，需要重跑平衡性相关的 AI 测试。

### 后续（非 MVP）
界限突破（宝物槽位 + 界武将）→ 国战（暗置 / 明置 / 野心家）→
联机匹配 → 搜索型 AI。

## 3. 风险清单与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 结算时机实现错误 | 规则不可信，全盘返工 | 先建时机枚举与栈；用官方 FAQ 建 Replay |
| 技能硬编码进流程 | 加武将越来越难 | 数据驱动 + 效果原语；禁止技能逻辑进主干；机械判据 = 源码纪律扫描（`tests/test_source_discipline.py` §5） |
| 隐藏信息泄露 | AI 作弊、回放失真 | Query 生成前强制可见性过滤 |
| 规则版本混淆 | 行为不一致 | 内容包 + 规则版本配置，显式声明 |
| 存疑点未决 | 实现反复 | 全部登记为决策项，在 `06` §4 与 §5「程序化约定与偏离一手」逐条裁定并落文档 |
| 非确定性 bug | 无法复现 | 单一随机源 + 事件日志 + 禁止时间/顺序依赖 |
| 范围蔓延 | 迟迟跑不通一局 | 严守 MVP 裁剪表，M1 先只做杀闪桃 |
| 数据录入错误 | 隐蔽的规则错误 | 加载期结构 + 语义校验；牌堆分布断言 |

## 5. 程序化约定与偏离一手

> 本节是**规则级**账本（一条裁定一行、入库）：凡"这条裁定从哪来"的问题，先查这里。
> `writeback.md` §3 仍做**票级**防翻案账本（本地、不入库），两者交叉引用、不互相复制全文。
> 本节是全部回写票的口径终点：`01` / `02` / `03` / `04` / `05` / `06` / `07` / `08` / `09` / `10` 的
> 裁定都登记在此。

**三类来源**（定义与 `GLOSSARY.md` 同名纪律词条逐字一致）：

- **程序化约定**——官方无一手条文，本项目自主定的执行口径。改了**不违背官方**。
- **偏离一手**——有官方明文，本项目明知而弃用。改回去等于**回归官方**，是一次**重新裁定**。
- **无一手源**——本机没有一手源，只能取社区通说或推断。只标注来源强度，**不构成裁定**。
