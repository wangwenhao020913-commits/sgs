# 03 数据模型与技能描述

本文件定义“规则引擎吃什么数据”。目标：**新增武将只加数据，不改引擎主干**。

---

## 1. 设计原则

1. **声明式优先**：能用数据描述的（牌名、花色、目标数、使用时机）不写逻辑。
2. **效果原语组合**：复杂技能 = 若干基础效果的组合 + 条件 + 时机。
3. **加载期校验**：数据在进入引擎前必须通过结构与语义校验，杜绝脏数据。
4. **版本可寻址**：同一武将可有标准版 / 界限突破版等多份技能定义。

> **M2 落地实况（依据票 09 / 票 12 / 票 30）**：原则 1 的"**目标数 / 使用时机 / 次数限制
> 进数据**"在 M2 **未落实**——这些行为字段仍由 `CardBehavior`（`src/sgs/effects/behaviors.py`）
> 承载，数据层只落**牌面事实**（牌名、类别、子类、花色、点数、颜色、攻击范围、延时声明）。
> 本文件其余各节保留初始设想的完整形状，**以本注标明哪些尚未落地**。

> **M3 落地注（依据 ADR-009；里程碑口径见 `06` §M3）**：M3 说的"**数据驱动**"只指
> **武将面进数据文件**——`id` / `name` / `kingdom` / `gender` / `hp_max` / `skills` / `version`
> 装进 `heroes.standard.json`；**技能定义仍住 `skills/` 的 Python**（回调不可序列化），
> `CATALOG` 仍是唯一入口。该裁定的完整登记见 `06` §4「决策记录（ADR）」 ADR-009。

## 2. 卡牌数据模型

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 字符串 | 唯一标识 |
| 名称 | 字符串 | 如“杀”“无中生有” |
| 类别 | 枚举 | 基本牌 / 锦囊牌 / 装备牌 |
| 子类 | 枚举 | 延时锦囊 / 非延时锦囊；武器 / 防具 / 防御马（+1 坐骑）/ 进攻马（−1 坐骑）/ 宝物 |
| 花色 | 枚举或空 | 虚拟牌可为空 |
| 点数 | 整数或空 | 1–13；虚拟牌可为空 |
| 颜色 | 枚举或空 | 红 / 黑 |
| 属性 | 枚举或空 | 普通 / 火焰 / 雷电 |
| 使用时机 | 字符串 | 出牌阶段 / 判定阶段等 |
| 目标规则 | 结构 | 额定目标数、是否含自己、距离要求、合法性约束 |
| 次数限制 | 结构 | 每回合次数、是否计入次数、是否受无距离限制 |
| 效果列表 | 结构列表 | 引用效果原语 |
| 内容包 | 字符串 | 标准 / 军争 / 界限突破 |

**示例性说明**（非代码）：
- 【杀】：目标数 1、要求攻击范围内、每回合限 1 次、效果 = 造成 1 点
  普通伤害（属性杀把“普通”换成火焰 / 雷电）。
- 【五谷丰登】：目标 = 所有角色、效果 = 亮出 N 张后依次选取。
- 【乐不思蜀】：延时锦囊、置入目标判定区、效果 = 判定非红桃则跳过
  出牌阶段。

> **M2 落地注（依据票 09 §7 / 票 12 §2 / 票 30）**：上表的「**使用时机 / 目标规则 /
> 次数限制 / 效果列表**」是设计设想，M2 **未进数据**——仍由 `CardBehavior`
> （`src/sgs/effects/behaviors.py`）承载；「**属性**」字段 M2 不存在（军争才引入，见 §5）。
> 数据层实际落的是 `CardType{id, name, category, subcategory, attack_range, delayed}`
> 与 `DeckCard{type, suit, rank}`。
> 装备子类的**五槽全名** = 武器 / 防具 / 防御马（+1 坐骑）/ 进攻马（−1 坐骑）/ 宝物，
> 与 `SlotKind` 的拼写一致（票 21 §⚠ P2 裁定；`horse_offense` = 进攻马、`horse_defense` = 防御马）。

## 3. 武将数据模型

| 字段 | 说明 |
|---|---|
| id / 名称 | 唯一标识 |
| 势力 | 魏 / 蜀 / 吴 / 群（扩展另有神、晋等） |
| 性别 | 男 / 女（影响【雌雄双股剑】【离间】等） |
| 体力上限 | 整数（主公 +1 由身份规则处理） |
| 武将包 | 标准 / 界限突破 / 风火林山等 |
| 技能列表 | 引用技能定义 |
| 版本 | 标准版 / 界限突破版等 |

> **M3 转正（依据票 01；数据文件 `heroes.standard.json`）**：武将表**不再是"暂时为空"**——
> 落定字段 = **`id` / `name` / `kingdom` / `gender` / `hp_max` / `skills` / `version`**，
> 技能条目带 `id` / `name` / `skill_type`；`kingdom`（**势力**：魏 / 蜀 / 吴 / 群）是**新增枚举**，
> `gender` 复用既有枚举。数据文件**装全标准版 25 名**，本局能发放谁由**启用门控**决定（见 §7）。
>
> **技能文字取规则文档第九章**（`三国杀详细规则.txt` 933–1054 行，"标准版武将（25 名）"）——
> **不取第十九章**（那是"界限突破·标准"29 名，按 ADR-006 数据分开存、MVP 不启用）。
>
> **体力上限改为读武将数据**（"主公 +1"的既有初始化逻辑不动，见下注）；开局参数允许**空武将池**
> = **无武将模式**，此模式下体力上限回落到引擎常数，M2 行为逐字节不变。

> **主公 +1 体力上限的落点（依据票 13 §1 / 票 19）**：M2 的落点是**初始化段**
> （`build_initial`），**不经武将数据**——身份规则直接把主公的体力上限 +1；M2 一个
> 武将都不落，武将表暂时为空。
>
> **模式派生（与 `02` 同族，依据票 13 §1）**：身份 / 模式由**座位数派生**——
> `player_count == 2 ⇒ 无身份局`；`4..8 ⇒ 身份局`；`3` 在**加载期失败**。身份局的
> `first_seat` **必须保持默认**（主公座位取代先手），**不得预设**。规则常数住
> `src/sgs/data/identities.py` / `rule_config.py`，不进武将数据。

## 4. 技能描述模型

M2 的技能形状落为 `SkillDef{skill_id, locked, carrier, hooks, modifiers}`
（`src/sgs/skills/catalog.py`）：

| 字段 | 说明 |
|---|---|
| `skill_id` | 技能的唯一标识 |
| `locked` | 锁定 / 非锁定（判据逐字取官方"牌面有没有『可以』"） |
| `carrier` | 载体类别（装备 / 武将 / 身份），决定优先级档 |
| `hooks` | 时机钩子列表（绑定到时机枚举） |
| `modifiers` | 修饰器列表（查询时修正一个值） |

**条件内联在回调**、**消耗不声明式**（依据票 07 §6）：

- 发动**条件**不是声明式布尔表达式，而是**回调自身**里的判断；
- **消耗**不在数据里声明，而由回调在**候选构造时**处理——付不起的组合不进候选，
  故不存在"答了发动才发现付不起"的中间态。

> 旧文写的"四元组（发动时机 / 发动条件 / 消耗 / 效果）"是设计初期的**声明式设想**，
> M2 未按它落地，保留于此以留证据链。

**触发次数**是技能定义的一部分：
- “受到伤害后” → 每次伤害事件一次；
- “受到 1 点伤害后” → 按点数逐点触发；
- “出牌阶段限一次” → 每个出牌阶段一次。

### 技能定义 / 实例 / 派发的冻结面（票 00：就地兑现 `03` §6「技能分类与过滤」的指针）

> M2 票 07 §6 的"冻结面"原先只住在非稳定工单里；本节把它**提拔进稳定文档**——
> `03` §6「技能分类与过滤」早已写着"该首项的形状由票 07 的冻结面持有"，本处即就地兑现那句指针，
> **不新开文档**。搬迁时把 M3 已落定的加法一并并入（见 ②）。

**① 冻结（M3 不得改名 / 改形）**

| 项 | 形状 |
|---|---|
| `SkillDef` | `skill_id: str` / `locked: bool` / `carrier: CarrierKind` / `hooks: tuple[Hook, …]` / `modifiers: tuple[Modifier, …]` |
| `Hook` / `Modifier` | `(timing: Timing, handler)` / `(point: ModifierPoint, handler)`；**无 `conditions` 字段** |
| handler 签名 | 钩子 `(host, frame) -> Control`；修饰器 `(state, ctx, current) -> new_value`，`ctx` 含 `(subject, target, role, …)` |
| 链序 / 优先级 | 链序 `(priority_class, skill_id)` 全序；`priority_class = HERO > EQUIPMENT > CARD_USE`（`02` §3.5(3) 的枚举化，**值序即链序**） |
| 定义目录 | `CATALOG: dict[skill_id, SkillDef]` 模块级不可变；`register(skill_def)` 是唯一入口 |
| 派发入口 | `dispatch_timing(host, frame, timing)` / `apply_modifiers(point, …)` |
| 实例键 | `(owner, skill_id, source)`；`source` 为带标签联合；per-instance 状态随 `source` 清理；按 `skill_id` 去重（最早存活来源胜出） |
| 虚拟装备 | 持久授予态、**不造 `CardRef`**；装备区只放实体牌；`is_equipped` = 实体 ∪ 虚拟；单轮解析、禁虚拟授予再授予 |
| 边界 | `skills/` 唯一入口；`engine/` 不出现具体 skill_id / 装备名（机械判据 = 源码纪律扫描 `tests/test_source_discipline.py`） |

**② M3 只许增（加法，不破坏签名）**

- `CarrierKind`：M2 = `{EQUIPMENT}`；M3 加 **`HERO`**、**`IDENTITY`**。
  （`IDENTITY` 按冻结面同为"只许增"的下一个加法，M3 **不落载体**——主公技的载体是**武将牌**，不是身份牌。）
- `SkillDef` 加 **`skill_type: SkillType`**（可选、带默认值，不破坏既有 17 条装备定义）。
- `Hook` 加 **`per_point`**（可选的"按点触发"声明；见本节"触发次数"与 ADR-010 的时机纪律）。
- `ModifierPoint`：M2 = `{COUNT_LIMIT, TARGET_POOL, DISTANCE, EFFECTIVENESS, CANDIDATES}`；
  M3 加 **`RESPONSE_COUNT`**（本次响应所需张数，缺省 1）与 **`RECOVER_AMOUNT`**（回复量，缺省 1）。
- 条件**允许清单**增长（接口不变）；`cost` 可选字段（若确需声明式消耗）。
- per-instance 状态：M2 只落"次数 / 已用"键位；限定技 / 觉醒技字段 M3 填（**载体不落**，见 ADR-008）。

**③ 显式标"M3 必改"**

- 定义来源：M2 Python 字面量 → M3 数据文件（**数据文件只装武将面**，字段名不变、新增加载器；
  技能定义仍在 `skills/` 的 Python，见 ADR-009）。
- `QueryKind` / `Action` 扩容**不在本冻结面内**（已毕业为 M2 票 19；M3 的 `ARRANGE` 询问与
  `ArrangeCards` 行动按同一门槛单独论证）。
- M2 dispatch 白名单 53 个之外，M3 解封更多时机（如 `MOVE_AFTER` 承接"失去装备后"）——
  **只解封一个枚举位，且只解封 after**（见 ADR-010）。

**两条 M3 约定**：

- **跨座位注入是合法用法**：技能回调可以把候选注入到**别人**的询问里（如某势力的角色在其
  出牌阶段可以主动把牌交给你），也可以把钩子挂在**别人的事件**上触发；引擎不为这类用法开新口子——
  它只是既有"候选提供者 + 时机钩子"的合法组合，不是需要特批的例外。
  势力作用域据此**不建字段**：一律由回调自己比座位——`ctx.owner`（技能持有者）对
  `ctx.subject`（本次决策者），或事件来源 `frame.data["source"]`，配只读的
  `sgs.skills.same_kingdom(state, a, b)`。M3 只**验证**机制不堵死这两个未来形态（不实现）：
  【黄天】式（`ctx.owner` = 持有者、`ctx.subject` = 别的势力角色，向其 `PLAY_PHASE` 注入候选）
  与【暴虐】式（钩子挂在别人的事件上，回调比 `frame.data["source"]` 判势力）——实测见
  `tests/test_hero_lord.py`。注意"只在需要者自己的实例上追加"是【八卦阵】【护驾】这类
  技能**自己的谓词**，不是平台约束。
- **`skill_type` 是闭集 `NORMAL` / `LORD`**（限定技 / 觉醒技是**预留取值、M3 无载体**，见 ADR-008）；
  它回答"这个技能属于哪一类"，与 `locked`（触发时要不要先确认发动）**正交**。

## 5. 效果原语（Effect Primitives）清单

引擎提供的基础积木，技能只能通过它们改变状态：

| 分类 | 原语 |
|---|---|
| 牌移动 | 摸牌、弃置、获得、交给、置于牌堆顶 / 底、置入判定区、移出游戏、重铸 |
| 体力 | 造成伤害、防止伤害、修改伤害值、失去体力、回复体力、增减体力上限 |
| 状态 | 翻面、重置、横置、解除横置、增加 / 移除标记、增减手牌上限 |
| 判定 / 拼点 | 发起判定、改判、发起拼点 |
| 使用 | 视为使用某牌、视为打出某牌、强制使用、禁止使用 |
| 控制 | 跳过阶段、执行额外回合、追加 / 取消目标、令牌无效 |
| 查询 | 查看手牌、观看牌堆顶、展示牌 |

**关键**：`视为使用 / 打出` 必须能表达“转化牌”与“纯虚拟牌”两种形态
（对应规则文档第十六章）：
- **转化牌**：有实体来源，**单张**继承原牌花色 / 点数 / 颜色；**属性不继承**——
  属性**由效果决定**，效果描述未声明则默认无属性（= 普通伤害）；
- **多张牌共同转化**（【丈八蛇矛】）：花色**恒无**、点数**恒无**，**颜色按来源牌
  同色派生**（同色 ⇒ 有该颜色，异色 ⇒ 无色）；见 `06` §4「决策记录（ADR）」 ADR-004；
- **纯虚拟牌**：无色、无点数、无属性。

> **查表派发：`CallOp` + op 注册表（依据票 08 / 票 09；M2 新增内容）**：效果步骤是
> union `EffectStep = PushFrame | CallOp`。`CallOp` 只带一个 **op 名**，引擎撞到它就查
> `sgs.effects.OPS` 注册表**按名通用派发**（回调签名统一 `(host, frame) -> Control`），
> `engine/` 里不出现任何具体效果名（门禁见 `tests/test_source_discipline.py` §5）。
> **`CallOp` 此前从未在本文件出现过，本项是新增而不是替换。**

> **区域坐标（`ZoneRef`）与移动来源（依据票 08 §1 / §4）**：牌移动类原语一律用
> **区域坐标** `ZoneRef(zone, seat)` 定位——`HAND` / `EQUIP` / `JUDGE` 是**逐座位**的区、
> 坐标带座位；`DECK` / `DISCARD` / `PROCESSING` 是共享区、座位为 `None`。
> 移动**来源**（`MoveReason`）的 M2 取值 = `DRAW` / `USE` / `DISCARD` / **`LOSE`** /
> **`PUT`** / **`JUDGE`**：`PUT` = 置入（如装备置入装备区）、`JUDGE` = 判定牌方向的移动、
> `LOSE` = 失去（如顶替时旧装备被移出、主动失去装备）。

> **修饰器 vs 帧标签的分界（依据票 08 / R4-Q1）**：**改一个值 ⇒ 修饰器**；**加一条禁令 / 标志 ⇒ 帧标签**。
> 前者是查询期对一个数值的链式修正（次数上限、目标池、距离、有效性、回复量、响应所需张数）；
> 后者是挂在**本次使用**上的一个标志（最典型是"不可响应"），分**全场档**与**逐目标档**、
> 随本次使用结束即结构性消失，且**不进记录流**。拿不准一个新效果该落哪侧时，先问它改的是
> "一个值"还是"这一次使用的一条禁令"。

> **`TARGET_POOL` 是链式管道：输入默认池、输出合法池（依据票 06 / R5-Q4）**：第 0 层先按
> 额定距离、附加谓词与延时锦囊的同名判定定出**默认池**，随后逐条修饰器把它换成**合法池**——
> 处理器可以**删目标**（【空城】【谦逊】这类"不能成为目标"的锁定技），也可以**不改**
> （【方天画戟】的既有处理器，明写"额外目标的合法性同标准"），M3 起还允许增目标。
> **候选生成与目标合法性校验读同一条链**：`check_targets` 是这条链的**唯一真源**，出牌阶段的
> 候选、被迫使用（【借刀杀人】的 Bn）与"视为使用"类效果的目标选取都不得绕开它——否则
> 强制指定目标的效果会绕过"不能成为目标"的锁定技。池被删空时**不新增终止语义**：出牌阶段
> 该牌不进候选；已经发生的使用走既有的"目标减为 0 ⇒ 终止使用流程、牌进弃牌堆"（`02` §3.3
> 的第 6 条）。

**花色 / 点数 / 颜色 / 属性的四形态**（ADR-003 / ADR-004 的落地附录；完整登记见
`06` §4「决策记录（ADR）」）：

| | 单源转化 | 多源转化 | 纯虚拟牌 |
|---|---|---|---|
| 花色 | 继承原牌 | 恒无 | 无 |
| 点数 | 继承原牌 | 恒无 | 无 |
| 颜色 | 继承原牌（按来源派生） | **按来源同色派生**（同色 ⇒ 有该颜色，异色 ⇒ 无色） | 无 |
| 属性 | **不继承**（一律不继承原牌；由效果决定） | **不继承**（由效果决定） | 无 |

> **属性这一行的读法**（ADR-003）：转化牌的属性**由效果决定**，效果描述未声明则默认
> 无属性（= 普通伤害）。因此【武圣】【龙胆】【丈八蛇矛】产生的【杀】都是**普通【杀】**，
> **不**继承来源牌的属性；颜色与属性是两条独立裁定——黑牌转化的【杀】仍会被【仁王盾】
> （黑色【杀】无效）挡下，而"普通【杀】"只影响【藤甲】一类按属性判定的效果。

## 6. 技能分类与过滤

| 类型 | 落地 | 引擎行为 |
|---|---|---|
| 锁定技 | ✅ | 满足条件自动执行，不询问 |
| 非锁定技 | ✅ | 生成"是否发动"询问（`SKILL_ACTIVATION`） |
| 主公技 | ✅ **转正（M3）** | **只有身份为主公时该技能才存在于武将牌上**；非主公时武将牌上**没有**它——不进实例、不进候选、不落随实例变化的状态、不进记录流 |
| 限定技 | ❌ **改判 M5**（M3 只建字段与 per-instance "已用"键、**不落载体**） | 记录已用状态，用后不再触发 |
| 觉醒技 | ❌ **改判 M5**（同上） | 条件满足强制发动，可附带减体力上限 |

M2 只落了 `locked`（锁定 / 非锁定）与主公技**接口位**（**M2 不可发动**）；
**M3 把主公技转正**——语义钉死为"只有身份为主公时该技能才存在于武将牌上"，
门控落在载体解析一处（非主公 ⇒ 实例不产出）；限定技 / 觉醒技**改判 M5**
（标准版 25 名**零载体**，见 ADR-008）。

过滤链：**势力过滤** → 身份过滤 → 存活过滤 → 状态过滤（如翻面、技能失效）→
时机过滤 → 条件过滤。首两环都是**归属级**：身份过滤 = 主公技的载体门控（非主公 ⇒ 实例不产出）；
势力过滤 = 势力作用域技能的应答者 / 候选者过滤（"其他同势力角色"，标准版三主公技都读它），
它**只对声明了势力作用域的技能生效**，不是全局约束。

> **身份过滤在 M2 无载体可过滤（依据票 07 的冻结面 / 票 19）**：M2 一个武将都不落，
> 主公技接口位也没有可发动的技能，故过滤链首项**暂无对象**；**M3 加武将后直接接入**——
> 首项的形状由 **§4「技能定义 / 实例 / 派发的冻结面」** 持有（票 00 已就地提拔），
> 身份门控落在载体解析这一处、以"不产出"兑现"武将牌上没有"。M2 **不算漏实现一环**。

## 7. 内容包与版本

| 内容包 | 内容 | 引擎影响 |
|---|---|---|
| 标准版 | 108 张牌 + 25 武将 | 基础 |
| 军争篇 | 52 张牌（属性杀、酒、铁索、藤甲等） | 增加属性伤害与连环机制 |
| 界限突破 | 界武将 + 木牛流马（宝物） | 装备区增加宝物槽位 |

加载时必须显式声明启用的内容包；不同包的同名武将按版本解析。

> **标准版装备计数（依据票 12 / 票 22）**：武器 **9 名 / 10 实体张**（诸葛连弩 ×2）、
> 防具 3、坐骑 6，合计 **19 张**。这是"按牌名 9、按实体张 10"的正确读法。

> **启用门控（依据票 01 / R4-Q5；ADR-009）**：数据文件**装全标准版 25 名**——不因"还没实现"
> 而砍表；**启用名单决定本局的武将池**（见 `GLOSSARY.md`「启用武将池」）：只有启用的武将可被发放，
> 发放走唯一随机源的专用子流、抽取不重复、按座位序分配。
>
> **加载期技能引用校验条件化**：`enabled` 的武将 ⇒ 其技能 id 必须在 `skills.CATALOG` 里存在；
> 未启用 ⇒ 只做**结构与唯一性**校验（id 唯一、体力上限为正整数、每名武将 ≥1 技能）。
> 于是"引用了一个不存在的技能"在加载期就红，而"技能还没实现"不会拦住整张表。
>
> 空武将池 = **无武将模式**：体力上限回落到引擎常数，M2 的 34 条基准继续有效。

## 8. 数据校验规则（加载期）

1. 结构校验：必填字段齐全、枚举值合法、数值范围正确。
2. 引用校验：技能引用的效果原语存在、卡牌引用的技能存在。
3. 语义校验：
   - 牌堆张数与花色点数分布符合规则文档第十章；
   - 每名武将至少一个技能，体力上限为正整数；
   - 延时锦囊必须声明"置入判定区"——落为 `CardType.delayed` 声明 + 加载期语义校验
     （`src/sgs/data/loader.py` 的校验第 5 条），且判定规则完整。
4. 冲突校验：同一内容包内 id 不重复；同名武将的不同版本必须带版本号。
5. 未通过校验的数据**不得加载**，并给出可定位的错误信息。
