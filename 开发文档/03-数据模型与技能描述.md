# 03 数据模型与技能描述

本文件定义“规则引擎吃什么数据”。目标：**新增武将只加数据，不改引擎主干**。

---

## 1. 设计原则

1. **声明式优先**：能用数据描述的（牌名、花色、目标数、使用时机）不写逻辑。
2. **效果原语组合**：复杂技能 = 若干基础效果的组合 + 条件 + 时机。
3. **加载期校验**：数据在进入引擎前必须通过结构与语义校验，杜绝脏数据。
4. **版本可寻址**：同一武将可有标准版 / 界限突破版等多份技能定义。

> **M2 落地实况（依据票 09 / 票 12 / 票 30）**：原则 1 的"**目标数 / 使用时机 / 次数限制
> 进数据**"在 M2 **未落实**——这些行为字段仍由 `CardBehavior`（`src/sgs/effects/behaviors.py`）
> 承载，数据层只落**牌面事实**（牌名、类别、子类、花色、点数、颜色、攻击范围、延时声明）。
> 本文件其余各节保留初始设想的完整形状，**以本注标明哪些尚未落地**。

---

## 2. 卡牌数据模型

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 字符串 | 唯一标识 |
| 名称 | 字符串 | 如“杀”“无中生有” |
| 类别 | 枚举 | 基本牌 / 锦囊牌 / 装备牌 |
| 子类 | 枚举 | 延时锦囊 / 非延时锦囊；武器 / 防具 / 防御马（+1 坐骑）/ 进攻马（−1 坐骑）/ 宝物 |
| 花色 | 枚举或空 | 虚拟牌可为空 |
| 点数 | 整数或空 | 1–13；虚拟牌可为空 |
| 颜色 | 枚举或空 | 红 / 黑 |
| 属性 | 枚举或空 | 普通 / 火焰 / 雷电 |
| 使用时机 | 字符串 | 出牌阶段 / 判定阶段等 |
| 目标规则 | 结构 | 额定目标数、是否含自己、距离要求、合法性约束 |
| 次数限制 | 结构 | 每回合次数、是否计入次数、是否受无距离限制 |
| 效果列表 | 结构列表 | 引用效果原语 |
| 内容包 | 字符串 | 标准 / 军争 / 界限突破 |

**示例性说明**（非代码）：
- 【杀】：目标数 1、要求攻击范围内、每回合限 1 次、效果 = 造成 1 点
  普通伤害（属性杀把“普通”换成火焰 / 雷电）。
- 【五谷丰登】：目标 = 所有角色、效果 = 亮出 N 张后依次选取。
- 【乐不思蜀】：延时锦囊、置入目标判定区、效果 = 判定非红桃则跳过
  出牌阶段。

> **M2 落地注（依据票 09 §7 / 票 12 §2 / 票 30）**：上表的「**使用时机 / 目标规则 /
> 次数限制 / 效果列表**」是设计设想，M2 **未进数据**——仍由 `CardBehavior`
> （`src/sgs/effects/behaviors.py`）承载；「**属性**」字段 M2 不存在（军争才引入，见 §5）。
> 数据层实际落的是 `CardType{id, name, category, subcategory, attack_range, delayed}`
> 与 `DeckCard{type, suit, rank}`。
> 装备子类的**五槽全名** = 武器 / 防具 / 防御马（+1 坐骑）/ 进攻马（−1 坐骑）/ 宝物，
> 与 `SlotKind` 的拼写一致（票 21 §⚠ P2 裁定；`horse_offense` = 进攻马、`horse_defense` = 防御马）。

## 3. 武将数据模型

| 字段 | 说明 |
|---|---|
| id / 名称 | 唯一标识 |
| 势力 | 魏 / 蜀 / 吴 / 群（扩展另有神、晋等） |
| 性别 | 男 / 女（影响【雌雄双股剑】【离间】等） |
| 体力上限 | 整数（主公 +1 由身份规则处理） |
| 武将包 | 标准 / 界限突破 / 风火林山等 |
| 技能列表 | 引用技能定义 |
| 版本 | 标准版 / 界限突破版等 |

> **主公 +1 体力上限的落点（依据票 13 §1 / 票 19）**：M2 的落点是**初始化段**
> （`build_initial`），**不经武将数据**——身份规则直接把主公的体力上限 +1；M2 一个
> 武将都不落，武将表暂时为空。
>
> **模式派生（与 `02` 同族，依据票 13 §1）**：身份 / 模式由**座位数派生**——
> `player_count == 2 ⇒ 无身份局`；`4..8 ⇒ 身份局`；`3` 在**加载期失败**。身份局的
> `first_seat` **必须保持默认**（主公座位取代先手），**不得预设**。规则常数住
> `src/sgs/data/identities.py` / `rule_config.py`，不进武将数据。

## 4. 技能描述模型

M2 的技能形状落为 `SkillDef{skill_id, locked, carrier, hooks, modifiers}`
（`src/sgs/skills/catalog.py`）：

| 字段 | 说明 |
|---|---|
| `skill_id` | 技能的唯一标识 |
| `locked` | 锁定 / 非锁定（判据逐字取官方"牌面有没有『可以』"） |
| `carrier` | 载体类别（装备 / 武将 / 身份），决定优先级档 |
| `hooks` | 时机钩子列表（绑定到时机枚举） |
| `modifiers` | 修饰器列表（查询时修正一个值） |

**条件内联在回调**、**消耗不声明式**（依据票 07 §6）：

- 发动**条件**不是声明式布尔表达式，而是**回调自身**里的判断；
- **消耗**不在数据里声明，而由回调在**候选构造时**处理——付不起的组合不进候选，
  故不存在"答了发动才发现付不起"的中间态。

> 旧文写的"四元组（发动时机 / 发动条件 / 消耗 / 效果）"是设计初期的**声明式设想**，
> M2 未按它落地，保留于此以留证据链。

**触发次数**是技能定义的一部分：
- “受到伤害后” → 每次伤害事件一次；
- “受到 1 点伤害后” → 按点数逐点触发；
- “出牌阶段限一次” → 每个出牌阶段一次。

## 5. 效果原语（Effect Primitives）清单

引擎提供的基础积木，技能只能通过它们改变状态：

| 分类 | 原语 |
|---|---|
| 牌移动 | 摸牌、弃置、获得、交给、置于牌堆顶 / 底、置入判定区、移出游戏、重铸 |
| 体力 | 造成伤害、防止伤害、修改伤害值、失去体力、回复体力、增减体力上限 |
| 状态 | 翻面、重置、横置、解除横置、增加 / 移除标记、增减手牌上限 |
| 判定 / 拼点 | 发起判定、改判、发起拼点 |
| 使用 | 视为使用某牌、视为打出某牌、强制使用、禁止使用 |
| 控制 | 跳过阶段、执行额外回合、追加 / 取消目标、令牌无效 |
| 查询 | 查看手牌、观看牌堆顶、展示牌 |

**关键**：`视为使用 / 打出` 必须能表达“转化牌”与“纯虚拟牌”两种形态
（对应规则文档第十六章）：
- **转化牌**：有实体来源，**单张**继承原牌花色 / 点数 / 颜色；**属性不继承**——
  属性**由效果决定**，效果描述未声明则默认无属性（= 普通伤害）；
- **多张牌共同转化**（【丈八蛇矛】）：花色**恒无**、点数**恒无**，**颜色按来源牌
  同色派生**（同色 ⇒ 有该颜色，异色 ⇒ 无色）；见 `06` §4「决策记录（ADR）」 ADR-004；
- **纯虚拟牌**：无色、无点数、无属性。

> **查表派发：`CallOp` + op 注册表（依据票 08 / 票 09；M2 新增内容）**：效果步骤是
> union `EffectStep = PushFrame | CallOp`。`CallOp` 只带一个 **op 名**，引擎撞到它就查
> `sgs.effects.OPS` 注册表**按名通用派发**（回调签名统一 `(host, frame) -> Control`），
> `engine/` 里不出现任何具体效果名（门禁见 `tests/test_source_discipline.py` §5）。
> **`CallOp` 此前从未在本文件出现过，本项是新增而不是替换。**

> **区域坐标（`ZoneRef`）与移动来源（依据票 08 §1 / §4）**：牌移动类原语一律用
> **区域坐标** `ZoneRef(zone, seat)` 定位——`HAND` / `EQUIP` / `JUDGE` 是**逐座位**的区、
> 坐标带座位；`DECK` / `DISCARD` / `PROCESSING` 是共享区、座位为 `None`。
> 移动**来源**（`MoveReason`）的 M2 取值 = `DRAW` / `USE` / `DISCARD` / **`LOSE`** /
> **`PUT`** / **`JUDGE`**：`PUT` = 置入（如装备置入装备区）、`JUDGE` = 判定牌方向的移动、
> `LOSE` = 失去（如顶替时旧装备被移出、主动失去装备）。

## 6. 技能分类与过滤

| 类型 | M2 落地 | 引擎行为 |
|---|---|---|
| 锁定技 | ✅ | 满足条件自动执行，不询问 |
| 非锁定技 | ✅ | 生成"是否发动"询问（`SKILL_ACTIVATION`） |
| 主公技 | 仅接口位 | **M2 不可发动**：只留身份过滤的接口位 |
| 限定技 | ❌ 归 M3 | 记录已用状态，用后不再触发 |
| 觉醒技 | ❌ 归 M3 | 条件满足强制发动，可附带减体力上限 |

M2 只落 `locked`（锁定 / 非锁定）与主公技**接口位**；主公技在 M2 **不可发动**，
限定技 / 觉醒技**归 M3**（依据票 07 §2 / 票 13）。

过滤链：身份过滤 → 存活过滤 → 状态过滤（如翻面、技能失效）→
时机过滤 → 条件过滤。

> **身份过滤在 M2 无载体可过滤（依据票 07 的冻结面 / 票 19）**：M2 一个武将都不落，
> 主公技接口位也没有可发动的技能，故过滤链首项**暂无对象**；该首项的**形状由票 07 的
> 冻结面持有**，M3 加武将时直接接入——M2 **不算漏实现一环**。

## 7. 内容包与版本

| 内容包 | 内容 | 引擎影响 |
|---|---|---|
| 标准版 | 108 张牌 + 25 武将 | 基础 |
| 军争篇 | 52 张牌（属性杀、酒、铁索、藤甲等） | 增加属性伤害与连环机制 |
| 界限突破 | 界武将 + 木牛流马（宝物） | 装备区增加宝物槽位 |

加载时必须显式声明启用的内容包；不同包的同名武将按版本解析。

> **标准版装备计数（依据票 12 / 票 22）**：武器 **9 名 / 10 实体张**（诸葛连弩 ×2）、
> 防具 3、坐骑 6，合计 **19 张**。这是"按牌名 9、按实体张 10"的正确读法。

## 8. 数据校验规则（加载期）

1. 结构校验：必填字段齐全、枚举值合法、数值范围正确。
2. 引用校验：技能引用的效果原语存在、卡牌引用的技能存在。
3. 语义校验：
   - 牌堆张数与花色点数分布符合规则文档第十章；
   - 每名武将至少一个技能，体力上限为正整数；
   - 延时锦囊必须声明"置入判定区"——落为 `CardType.delayed` 声明 + 加载期语义校验
     （`src/sgs/data/loader.py` 的校验第 5 条），且判定规则完整。
4. 冲突校验：同一内容包内 id 不重复；同名武将的不同版本必须带版本号。
5. 未通过校验的数据**不得加载**，并给出可定位的错误信息。
