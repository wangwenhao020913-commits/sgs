# 05 测试与验证策略

目标：让“规则正确”成为可自动验证的事实，而不是靠人肉试玩。
本项目 `AGENTS.md` 已强制要求：**每次改动都要提交，并跑通测试**。

---

## 1. 测试金字塔

```
        ┌──────────────────────┐
        │  验收：AI 整局跑通     │  少量、慢、覆盖端到端
        ├──────────────────────┤
        │  集成：Golden Replay  │  固定种子 + 脚本行动
        ├──────────────────────┤
        │  单元：规则/效果/时机  │  大量、快、定位精确
        └──────────────────────┘
```

## 3. Golden Replay（集成测试核心）

机制：
1. 固定随机种子；
2. 用**脚本玩家**给出预设行动序列；
3. 运行引擎，导出事件日志；
4. 与基准日志逐条比对（或比对关键断言）；
5. 不一致即失败，并输出首个分歧点。

用途：
- 防止“修一个规则、坏另一个规则”的回归；
- 把规则文档中官方 FAQ 的“例如”直接转成 Replay 用例；
- 赛博取证：规则争议时用日志复盘。

管理约定：
- 基准日志纳入版本管理，变更必须说明原因；
- 每个基准附带“本用例验证的规则条目”注释。

## 4. 不变量测试（Property）

无论进行到哪一步，以下不变量恒成立：

| 不变量 | 说明 |
|---|---|
| 牌守恒 | 全部牌实例在“牌堆 + 手牌 + 装备 + 判定 + 处理区 + 弃牌堆 + 移出游戏”中且不重复 |
| 体力范围 | 0 ≤ 当前体力 ≤ 体力上限（濒死结算中间态除外） |
| 区域互斥 | 一张实体牌任一时刻只在一个位置 |
| 手牌上限 | 弃牌阶段结束后，存活角色手牌数 ≤ 手牌上限 |
| 判定区唯一 | 同角色判定区不能有两张同名延时锦囊 |
| 事件单调 | 事件序号严格递增、无回退 |

用随机对局（fuzz）大量运行，任何一次违反都算失败。

---

## 5. 时机与顺序测试

专门覆盖最易错的“顺序”问题：
- 同一时点多技能：由角色自选顺序，结果应随选择变化；
- 多角色响应：从当前回合角色起逆时针，且每人一次；
- 插入结算：伤害 → 濒死 → 救回 → 继续伤害后技能；
- 连环传导：一次属性伤害引发的多次伤害结算顺序；
- 目标减为 0：终止使用流程并置入弃牌堆。

## 7. 门禁与交付标准

1. **每次改动必须有 commit**（`AGENTS.md` 第 1 条）。
2. **每次改动必须编写 / 更新测试并跑通**（第 2 条）。
3. 合并前必须通过：单元测试 + Golden Replay + 不变量 fuzz（短时）。
4. 规则文档变更时，必须同步更新对应的规则测试与本文档第 2 节映射表。
5. 存疑点决策变更（如无懈窗口）必须同时更新配置、测试与决策记录。
