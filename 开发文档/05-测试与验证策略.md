# 05 测试与验证策略

目标：让“规则正确”成为可自动验证的事实，而不是靠人肉试玩。
本项目 `AGENTS.md` 已强制要求：**每次改动都要提交，并跑通测试**。

## 3. Golden Replay（集成测试核心）

机制：
1. 固定随机种子；
2. 用**脚本玩家**给出预设行动序列；
3. 运行引擎，导出事件日志；
4. 与基准日志逐条比对（或比对关键断言）；
5. 不一致即失败，并输出首个分歧点。

用途：
- 防止“修一个规则、坏另一个规则”的回归；
- 把规则文档中官方 FAQ 的“例如”直接转成 Replay 用例；
- 赛博取证：规则争议时用日志复盘。

管理约定：
- 基准日志纳入版本管理，变更必须说明原因；
- 每个基准附带“本用例验证的规则条目”注释。

## 4. 不变量测试（Property）

无论进行到哪一步，以下不变量恒成立：

| 不变量 | 说明 |
|---|---|
| 牌守恒 | 全部牌实例在“牌堆 + 手牌 + 装备 + 判定 + 处理区 + 弃牌堆 + 移出游戏”中且不重复 |
| 体力范围 | 0 ≤ 当前体力 ≤ 体力上限（濒死结算中间态除外） |
| 区域互斥 | 一张实体牌任一时刻只在一个位置 |
| 手牌上限 | 弃牌阶段结束后，存活角色手牌数 ≤ 手牌上限 |
| 判定区唯一 | **规则层候选过滤**的结果：同名的延时类锦囊不是合法目标（官方 17.10），故区域里不会出现两张同名。**不是区域不变量**——区域模型本身不做该约束 |
| 事件单调 | 事件序号严格递增、无回退 |

> **口径更正（依据票 21 / 票 26 / 票 27）**：判定区同名唯一由**规则层候选过滤**保证
> （官方 17.10 明文"不是合法目标"），**不是区域不变量**；但 fuzz 不变量「判定区同名唯一」
> 本身**保留**（它验证的是过滤生效后的结果，不是要求区域模型自己拦）。与 `02` §2.2 同口径。

用随机对局（fuzz）大量运行，任何一次违反都算失败。

## 5. 时机与顺序测试

专门覆盖最易错的“顺序”问题。本节按 **T-2** 补两类（「插入结算顺序」与「不属于任何角色的
回合起点」）：先核对 M1 的覆盖（`tests/test_resolution_stack.py` / `tests/test_turn_loop.py` /
`tests/test_near_death.py`），已覆盖的把落点写在条目后，走不到的显式登记里程碑。
**不得**因为“这版不做”而从本节删除（口径见 §2）。

- **回合环顺序**（T-2）：6 个阶段 + 5 个阶段间按序推进；**判定阶段不是空阶段**——它走
  判定事件（对判定区里"最后置入"的延时锦囊发起判定），与术语表「判定阶段不是空阶段」一致。
  M1 落点 `tests/test_turn_loop.py`；各基准顺带；
- **同一时点多技能**：由角色自选顺序，结果应随选择变化（M1 无技能，时机枚举位保留；M3 承接）；
- **多角色响应**（T-2）：从当前回合角色起逆时针、每人一次。M1 落点 `tests/test_near_death.py`
  （`PEACH` 窗口按官方 L12.2 逐个发问、一个询问一个应答者）；基准 `04` / `05` 顺带；
- **插入结算顺序**（T-2，官方「后发先至」）：子结算整段跑完，再回到父结算被打断处继续
  （`pc` 续跑），故记录流里 `depth` 逐层加深、`return_to` 读出“从哪回来”。M1 落点：
  `tests/test_use_and_resolve.py`（伤害帧嵌在扣减体力帧之内，`LIFE_DECREASE_*` 落在
  `DAMAGE_TAKE` 与 `DAMAGE_AFTER_DEAL` 之间）、`tests/test_near_death.py`（回复帧插在
  濒死帧之下、救回后回到被中断的扣减体力结算）、`tests/test_death.py`（死亡帧挂在濒死帧
  之上、M1 裁剪后的四段跑完才清栈）、`tests/test_resolution_stack.py`（显式栈帧 + `pc` /
  `Goto` / 命名式恢复点 / 出栈记录）；基准 `02-slash-hit-damage` 覆盖整局形态；
- **不属于任何角色的回合起点**（T-2，官方 L18.8）：两个起点由同一条调度规则给出——
  从「死亡结算开始」到「死亡时」**从该角色起**，「死亡时」之后**从其下家起**。M1 只保留
  结构：应答者区间把起点做成参数（`None` 退化为座位 0 起，`src/sgs/engine/steps.py`），
  但死亡结算里切换起点的分支未落地；核对 `tests/test_turn_loop.py` 的回合环后确认 M1
  每回合都有明确 `turn_seat`，且 1v1 每次死亡都直接终局，**实战走不到**，故**登记为 M2**：
  随身份局 / 死亡奖惩补「构造局面 + 起点切换」单测（依据票 05 §7、票 13 §5、票 12 场景 13；
  票 13 §5 答应的 M1 结构测试未落地，本票据实登记而非默认已覆盖）；
- **连环传导**：一次属性伤害引发的多次伤害结算顺序（军争，M5）；
- **目标减为 0**：终止使用流程并置入弃牌堆（M1 跳过；M2 引入改变 / 取消目标的效果时回补）。

## 7. 门禁与交付标准

1. **每次改动必须有 commit**（`AGENTS.md` 第 1 条）。
2. **每次改动必须编写 / 更新测试并跑通**（第 2 条）。
3. 合并前必须通过：单元测试 + Golden Replay + 不变量 fuzz（短时）。
4. 规则文档变更时，必须同步更新对应的规则测试与本文档第 2 节映射表。
5. 存疑点决策变更（如无懈窗口）必须同时更新测试与决策记录。
