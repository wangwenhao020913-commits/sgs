# 02 规则引擎设计

本文件描述 `rules-core` 的结构设计。**不含实现代码**，只定义概念、数据
边界与行为规则。

---

## 1. 引擎职责

引擎只做四件事：

1. **维护状态**：对局的全部事实（角色、牌、区域、标记、时机）。
2. **校验行动**：判断某个 Action 当前是否合法，不合法则给出原因。
3. **推进结算**：应用行动，按时机触发技能与效果，必要时插入子结算。
4. **抛出询问**：需要决策时生成 Query，交由参与者应答。

引擎**不做**：渲染、计时、网络、AI 策略。

## 2. 状态模型

### 2.1 顶层状态
| 字段 | 含义 |
|---|---|
| 对局标识 | 唯一 id、随机种子、规则版本、内容包列表 |
| 角色列表 | 全部座位（含已死亡，保留历史） |
| 牌堆 / 弃牌堆 | 有序牌实例列表 |
| 处理区 | 当前正在结算的实体牌 |
| 当前回合 | 当前回合角色、所处阶段与时机 |
| 轮次 | 当前轮次、本轮起始座位、自然指针与额外回合待执行栈（M6 新增；额外回合不推进自然指针） |
| 结算栈 | 尚未结算完的嵌套事件 |
| 等待项 | 当前是否有 Query 待应答，应答者是谁 |
| 事件序号 | 单调递增，用于日志与复现 |
| 阶段标记 | 是否已结束、胜利方 |

### 2.2 角色
| 字段 | 含义 |
|---|---|
| 座位号 | 决定行动顺序与距离 |
| 身份 | 主公 / 忠臣 / 反贼 / 内奸（仅自己可见，死亡后公开） |
| 武将 | 武将 id、势力、性别 |
| 体力 | 当前体力值 / 体力上限 |
| 状态 | 存活、翻面（背面朝上）、横置（连环状态） |
| 手牌区 | 手牌实例列表 |
| 装备区 | 武器 / 防具 / 防御马（+1 坐骑）/ 进攻马（−1 坐骑）**四槽**；宝物槽位只留枚举位、不启用（ADR-006 / M6 spec D7） |
| 判定区 | 延时类锦囊实例列表（不能有两张同名） |
| 武将牌上 | **武将牌上的牌**：按（座位, 技能实例）彼此独立的放置区，可跨座位；放置类技能须在数据里声明可见性 / 归还时机 / 附加效果（§2.5） |
| 标记 | 名称 → 数量 |
| 技能状态 | 已获得 / 失效 / 已用次数 / 限定技是否已用 |

> **判定区同名的归属（口径更正，依据票 21 / 票 26 / 票 27）**：上表"不能有两张同名"由
> **规则层候选过滤**保证（官方 17.10 明文"同名的延时类锦囊不是合法目标"），**不是区域
> 不变量**——区域模型本身不做该约束。fuzz 不变量"判定区同名唯一"仍**保留**（它验证的
> 是过滤生效后的结果），与 `05` §4「不变量测试」同口径。

### 2.3 牌实例
| 字段 | 含义 |
|---|---|
| 实例 id | 唯一，转化与多张合成时用于追踪实体 |
| 牌名 / 类别 | 基本牌 / 锦囊牌 / 装备牌及其子类 |
| 花色 / 点数 | 判定与拼点的依据；虚拟牌可为“无” |
| 颜色 / 属性 | 红黑、火焰 / 雷电 / 普通 |
| 位置 | 牌堆 / 手牌 / 装备区 / 判定区 / 武将牌上的牌 / 处理区 / 弃牌堆 / 移出游戏 |
| 归属 | 拥有者（判定区与移出游戏的牌不归任何人） |
| 来源 | 打出 / 使用 / 判定 / 拼点等产生方式 |

### 2.4 虚拟牌与转化
- **转化牌**：有实体来源。**单张**转化继承原牌花色 / 点数 / 颜色；**属性不继承**——
  属性**由效果决定**，效果描述未声明则默认无属性（= 普通伤害）。仅牌名改写
  （依据：本地一手 16.3，技能转化【杀】视为普通【杀】，不带属性；见 `06` §4「决策记录（ADR）」 ADR-003）。
- **多张牌共同转化**（如【丈八蛇矛】两张手牌当【杀】）：花色**恒无**、点数**恒无**；
  **颜色按来源牌同色派生**（来源牌同色 ⇒ 有该颜色，异色 ⇒ 无色）。官方通则的
  "颜色规则 + 点数和"**不采用**（用户裁定；见 `06` §4「决策记录（ADR）」 ADR-004 与 §5「程序化约定与偏离一手」）。
- **虚拟牌**：无实体，标记为"无花色 / 无点数 / 无属性 / 无实体"。
- 引擎须能同时表达“牌名”与“实体来源”，供【武圣】【奇袭】【急救】
  【激将】【护驾】等使用（对应规则文档第十六章）。

### 2.5 武将牌上的牌（M6 新增）

**武将牌上的牌**是一个**真区域**（`Zone.HERO`），不是"移出游戏"的无坐标列表：它过搬牌
原语（`locate` / `GameState.zone` / `move_card`），因此区域互斥、牌守恒与 `card_move`
都走既有唯一入口。区键 = **放置技能的实例键**（`owner:skill_id`）+ **扣牌宿主的座位**：
同一座位可同时有多个互不相同的放置区，不同技能的区**互不可见、互不归还**；区可跨座位
（把牌扣在别人的武将牌上）。

放置类技能必须在数据里显式声明三项——**可见性**、**归还时机**、**有无附加效果**；缺一项
判红，加载期与代码侧（`SkillDef.places_on_hero_card`）双向核对。这些牌**不在手牌区**
（不计手牌数 / 手牌上限、不进拆顺候选），也不因放置者失去技能而被弃置（死亡清区由引擎
按规则 15.3 统一处理）。

> **与官方的偏离（`06` §5「程序化约定与偏离一手」登记）**：官方第十五章 15.1 把"置于
> 武将牌上的牌"定义成"移出游戏的牌、不在任何区域"；本项目用**真区域**建模（有坐标、
> 过搬牌原语），对外的 15.2 性质原样守住。偏离点只在建模分类，不在规则结果。

### 2.6 轮次与额外回合（M6 新增）

- **轮次**（`round`，从 1 起）是**派生自自然指针**的对局事实：自然指针（`next_seat`）
  只在**非额外回合**结束时前进；回到（或越过）本轮起始座位（`round_start_seat`）时
  轮次 +1。"越过"覆盖本轮起点中途阵亡的情形，否则轮次会卡死。
- **额外回合**用**显式待执行栈**（`extra_turns`）：回合结束时压入、下个回合开始时弹出
  接管（LIFO、跳过已阵亡者），**不推进自然指针**——故额外回合不刷新「每轮限 X 次」。
- **记录流**：`turn_change` delta（`seat` / `round` / `extra`）只在**本局存在「每轮限 X
  次」载体**时落盘；没有读者时轮次不改变任何规则结果，标准金录像因此逐字节不变。
- **两个作用域**：「每轮限 X 次」的已用计数住 `round_use_counts`，唯一复位点 = 轮次 +1；
  「本回合」类状态（【酒】/【裸衣】/ 博图的花色记账）仍按**回合**复位，额外回合各有一份。

## 3. 时机系统（引擎核心）

引擎把一局的推进切成一条**时机链**，技能与效果注册到时机上。权威时机表由
`sgs.timing.Timing` 一次建全，共 **83 个时机节点**，与《三国杀详细规则.txt》
3.9 / 4.13–4.19 / 17.10–17.13 一一对应（依据：票 01 研究
`.scratch/m1-engine-skeleton/research/01-timing-enum-alignment.md` §1）。时机节点按**载体**分层：

| 层 | 载体 | 节点数 |
|---|---|---|
| `L0` | 游戏级（回合之外，一局一次） | 3 |
| `L1` | 回合级 | 2 |
| `L2` | 阶段层（每回合） | 25 |
| `L4` | 使用结算前（每次使用） | 6 |
| `L5` | 使用结算中 + 使用结算后（每个使用事件 × 每个目标） | 6 |
| `L6`–`L17` | 其它事件（每发生一次走一遍） | 41 |
| 合计 | **时机节点** | **83** |

表中**标识符即枚举值**，也是事件记录里时机字段的取值（见 §7）；层号与层内序号
由枚举派生、**不落盘**（票 06 §4）。整表冻结：以后加技能只注册到已有节点，不改
枚举值与顺序；伪时机禁令与完整性由 `tests/test_timing.py` 机械断言。

推进绑定分两种粒度，贯穿 §3.2 / §3.3：

- **牌级**（`L4`）：对一张牌**所有目标**处理完一个时机，再进入下一个时机；
- **逐目标**（`L5`）：对一个目标连续走完 `L5.1`–`L5.5`，再处理下一个目标；
  同一目标被多次结算时，连续走完该目标的每一轮 `L5`；全部目标处理完后由 `L5.6`
  做一次牌级收尾。

### 3.0 使用前校验（`L3`，**非时机**）

使用一张牌之前的三项合法性检测（规则文档 17.10【A】）。它们没有官方时机名，
**不得**作为时机值进枚举或写入记录字段：

| 校验步骤 | 校验函数（非 `Timing` 成员） | 研究 L3 标签 | 说明 |
|---|---|---|---|
| 禁止使用牌效果检测 | `check_forbidden` | `USE_CHECK_FORBIDDEN` | 是否存在禁止该角色使用此牌的效果 |
| 使用次数检测 | `check_count` | `USE_CHECK_COUNT` | 额定次数与额外次数是否都已达上限 |
| 额定目标合法性检测 | `check_targets` | `USE_CHECK_TARGETS` | 至少一个合法额定目标（距离 + 选择合法性） |

三项落在 §6 行动模型的校验层（“当前合法行动集合”）；时机链从 `L4` 开始。

### 3.1 游戏级、回合级与阶段时机（`L0`–`L2`）

**`L0` 游戏级（回合之外，一局一次）**

| 时机 | 标识符 | 说明 |
|---|---|---|
| 游戏开始前亮出武将牌后 | `GAME_HERO_REVEALED` | 所有武将牌亮出完毕、尚未发牌 |
| 游戏开始前分发起始手牌时 | `GAME_INITIAL_HAND_DEALING` | 正在分发起始手牌 |
| 游戏开始时 | `GAME_START` | 起始手牌分发完毕、第一个回合开始之前 |

**`L1` 回合级**

| 时机 | 标识符 | 说明 |
|---|---|---|
| 回合开始前 | `TURN_BEFORE_START` | 背面朝上则先翻面并跳过整个回合 |
| 回合开始时 | `TURN_START` | “回合内”从此时机开始 |

**`L2` 阶段层（每回合 25 个节点）**

每个阶段的“开始时 / 阶段 / 结束时”三个节点，加相邻阶段之间的“阶段间”节点：

| 时机 | 标识符 |
|---|---|
| 准备阶段开始时 / 准备阶段 / 准备阶段结束时 | `PHASE_PREPARE_START` / `PHASE_PREPARE` / `PHASE_PREPARE_END` |
| 准备阶段与判定阶段间 | `INTERVAL_PREPARE_TO_JUDGE` |
| 判定阶段开始时 / 判定阶段 / 判定阶段结束时 | `PHASE_JUDGE_START` / `PHASE_JUDGE` / `PHASE_JUDGE_END` |
| 判定阶段与摸牌阶段间 | `INTERVAL_JUDGE_TO_DRAW` |
| 摸牌阶段开始时 / 摸牌阶段 / 摸牌阶段结束时 | `PHASE_DRAW_START` / `PHASE_DRAW` / `PHASE_DRAW_END` |
| 摸牌阶段与出牌阶段间 | `INTERVAL_DRAW_TO_PLAY` |
| 出牌阶段开始时 / 出牌阶段空闲时间点 / 出牌阶段结束时 | `PHASE_PLAY_START` / `PHASE_PLAY_IDLE` / `PHASE_PLAY_END` |
| 出牌阶段与弃牌阶段间 | `INTERVAL_PLAY_TO_DISCARD` |
| 弃牌阶段开始时 / 弃牌阶段 / 弃牌阶段结束时 | `PHASE_DISCARD_START` / `PHASE_DISCARD` / `PHASE_DISCARD_END` |
| 弃牌阶段与结束阶段间 | `INTERVAL_DISCARD_TO_FINISH` |
| 结束阶段开始时 / 结束阶段 / 结束阶段结束时 | `PHASE_FINISH_START` / `PHASE_FINISH` / `PHASE_FINISH_END` |
| 回合结束时 / 回合结束后 | `TURN_END` / `TURN_AFTER_END` |

> **出牌阶段空闲时间点**（`PHASE_PLAY_IDLE`）：出牌阶段内有无数个空闲时间点，
> 每一个空闲时间点都是一个独立时机；只有处于空闲时间点才能使用牌 / 发动
> “出牌阶段”类技能，阶段内正插入其它事件的结算时不是空闲时间点。
> “该角色的回合内”以 `TURN_START` 为起点、`TURN_AFTER_END` 为终点。

### 3.2 使用结算前（`L4`，六个，**牌级**）

**牌级**：所有目标处理完一个时机再进入下一个时机（规则文档 17.10【B】）。

| 序 | 时机 | 标识符 | 说明 |
|---|---|---|---|
| 1 | 选择目标时 | `USE_CHOOSE_TARGET` | 声明牌名 + 选合法目标 + 展示实体牌；实体牌置入处理区 / 判定区 / 装备区 |
| 2 | 使用时 | `USE_ON_USE` | 实体牌已置入目标区域之后 |
| 3 | 指定目标时 | `USE_DESIGNATE_TARGET` | 使用者指定目标 |
| 4 | 成为目标时 | `USE_BECOME_TARGET` | 此牌的目标可能被改变或追加 |
| 5 | 指定目标后 | `USE_AFTER_DESIGNATE_TARGET` | 目标确定，不再改变 |
| 6 | 成为目标后 | `USE_AFTER_BECOME_TARGET` | 成为目标的最终确认 |

> 若使用结算前某目标数量减为 0，则在插入的结算完毕后**终止使用流程**，把实体牌
> 置入弃牌堆。

### 3.3 使用结算中与使用结算后（`L5`，**逐目标**）

**逐目标**：一个目标的 `L5.1`–`L5.5` 连续走完，再对下一个目标重复；全部目标处理
完毕后才做一次**牌级收尾** `L5.6`。同一目标被多次结算时，连续走完该目标的每一轮
`L5`。

| 序 | 时机 | 标识符 | 说明 |
|---|---|---|---|
| 1 | 使用结算开始时 | `RESOLVE_START` | 检测此牌对**该目标**的有效性；无效则终止对该目标的结算 |
| 2 | 生效前 | `RESOLVE_BEFORE_EFFECT` | 可对此牌响应（【闪】响应【杀】、【无懈可击】响应锦囊）；被抵消则跳过“生效时 / 生效后” |
| 3 | 生效时 | `RESOLVE_EFFECT` | 未被抵消，确定将会生效 |
| 4 | 生效后 | `RESOLVE_AFTER_EFFECT` | 执行此牌的效果；产生伤害则插入伤害结算 |
| 5 | 使用结算结束时 | `RESOLVE_END` | 该目标的使用结算结束 |
| 6 | 使用结算结束后 | `RESOLVE_AFTER_END` | **牌级收尾（全部目标之后一次）**：处理区里此牌对应的实体牌置入弃牌堆（装备牌留在装备区） |

> **口径说明（登记待定，不静默取舍）**：规则文档 17.10【C】把 `L5.1`–`L5.5` 合称
> “使用结算中：五个时机（逐个目标结算）”，研究 §1 的 L5 表头与此一致；官方流程页
> 另有一句“对一个目标处理完……直到使用结算结束时**之前**为止……直到所有目标都处理
> 完毕，进入使用结算结束时”。M1 只有单目标使用，两种读法等价；多目标前须在票 04 /
> M2 依一手规则定死。

### 3.4 其它事件时机（`L6`–`L17`）

每个事件发生时，按下列顺序走一遍它自己的时机。各表标识符与 `sgs.timing`
一一对应。

**打出事件（`L6`）**

| 序 | 时机 | 标识符 | 说明 |
|---|---|---|---|
| 1 | 声明打出的牌名时 | `PLAY_DECLARE` | 声明牌名 + 展示实体牌；**声明即视为响应成功** |
| 2 | 打出牌时 | `PLAY_ON_PLAY` | 实体牌已置入处理区之后 |

> 打出结算完毕，处理区里此牌对应的实体牌置入弃牌堆。打出不指定目标、不占使用
> 次数，不走 `L4` / `L5`（规则文档 17.11 / 17.12）。

**伤害事件（`L7`，八个）**

| 序 | 时机 | 标识符 |
|---|---|---|
| 0 | 伤害结算开始前 | `DAMAGE_BEFORE_START` |
| 1 | 伤害结算开始时 | `DAMAGE_START` |
| 2 | 造成伤害时 | `DAMAGE_DEAL` |
| 3 | 受到伤害时 | `DAMAGE_TAKE` |
| 4 | 造成伤害后 | `DAMAGE_AFTER_DEAL` |
| 5 | 受到伤害后 | `DAMAGE_AFTER_TAKE` |
| 6 | 伤害结算结束时 | `DAMAGE_END` |
| 7 | 伤害结算结束后 | `DAMAGE_AFTER_END` |

> **「防止伤害」不是独立时机**：官方把防止伤害表达为在 `DAMAGE_DEAL` /
> `DAMAGE_TAKE` **把伤害值减为 0**——伤害减为 0 即防止全部点数的伤害，并视为伤害来源
> 未造成过、目标未受到过伤害，结算完毕后直接进入 `DAMAGE_END`。伤害中产生的
> 扣减体力走独立的体力类事件（`L8`），体力被扣减至 0 时插入濒死结算（`L12`）。

**体力类事件（`L8`–`L11`）**

四类数值变化事件互相独立、分别建模、不可合并（规则文档 4.13）：

| 事件 | 时机（标识符） | 说明 |
|---|---|---|
| 扣减体力 | `LIFE_DECREASE_BEFORE` → `LIFE_DECREASE_ON` → `LIFE_DECREASE_AFTER` | 三时机；`LIFE_DECREASE_ON` 体力被扣减至 0 则**插入濒死结算**（`L12`） |
| 失去体力 | `LIFE_LOSE_ON` → `LIFE_LOSE_AFTER` | `LIFE_LOSE_ON` 可防止失去体力，否则转入扣减体力结算；无来源、无属性 |
| 回复体力 | `RECOVER_VALUE` → `RECOVER_AFTER` | 第 1 个时机官方叫**确定回复数值**，没有“回复体力时” |
| 减体力上限 | `MAXLIFE_DECREASE_BEFORE` → `MAXLIFE_DECREASE_AFTER` | 上限减为 0 直接死亡、不进入濒死（`L13`） |
| 加体力上限 | `MAXLIFE_INCREASE_BEFORE` → `MAXLIFE_INCREASE_AFTER` | 加 / 减是两个独立流程，只有“前 / 后”，没有“增减体力上限时” |

**濒死事件（`L12`）**

| 序 | 时机 | 标识符 |
|---|---|---|
| 1 | 进入濒死状态时 | `NEAR_DEATH_ENTER` |
| 2 | 处于濒死状态时 | `NEAR_DEATH_AT` |
| 3 | 濒死结算结束后 | `NEAR_DEATH_AFTER` |

> `NEAR_DEATH_AT` 的询问从当前回合角色起按逆时针方向依次进行，直到体力首次回复
> 至 1 点或以上。**新濒死回退**：新的“处于濒死状态时”由 B 起、到当前回合角色的
> 上家为止依次响应（规则文档 4.17）。濒死结算优先于“造成 / 受到伤害后”类技能。

**死亡事件（`L13`，五段）**

| 序 | 时机 | 标识符 | 说明 |
|---|---|---|---|
| 0 | 死亡结算开始前 | `DEATH_BEFORE_START` | 主公主死则游戏结束；否则在其自己的回合内死亡则其回合结束，并判定“是否视为某伤害来源杀死过” |
| 1 | 亮出身份牌前 | `DEATH_REVEAL_IDENTITY_BEFORE` | 结算该时机技能，然后亮出身份牌 |
| 2 | 亮出身份牌后 | `DEATH_REVEAL_IDENTITY_AFTER` | **检测是否满足游戏结束的条件（胜负判定点）** |
| 3 | 死亡时 | `DEATH_ON` | 技能时机；随后系统处理死亡角色的牌，再**执行奖惩**（实现上这两段是紧随其后的非 dispatch 步 `death_settle_cards`，见下） |
| 4 | 死亡后 | `DEATH_AFTER` | 死亡结算的最后一个时机 |

> **位置纠偏**：胜负检测在 `DEATH_REVEAL_IDENTITY_AFTER`（亮出身份牌后），不是笼统的
> “死亡后（奖惩与胜负判定）”（规则文档 4.18；依据 `G-9`）。奖惩属于「死亡时」这一步的
> 第 Ⅱ 段（Ⅰ.a 系统处理牌 → Ⅱ 奖惩）；实现上它**不与** `DEATH_ON` 的时机 dispatch 同一
> 格，而是紧随其后的非 dispatch 步 `death_settle_cards`（`src/sgs/engine/steps.py`）——
> 奖惩里的搬牌会挂起，拆开它续跑才不会重发 `DEATH_ON` 的时机记录（票 33）。

**判定事件（`L14`）**

| 序 | 时机 | 标识符 |
|---|---|---|
| 1 | 判定时 | `JUDGE_ON` |
| 2 | 判定牌生效前 | `JUDGE_CARD_BEFORE_EFFECT` |
| 3 | 判定牌生效后 | `JUDGE_CARD_AFTER_EFFECT` |

**拼点事件（`L15`，仅两个时机）**

| 序 | 时机 | 标识符 |
|---|---|---|
| 1 | 进行拼点时 | `RANK_COMPARE_ON` |
| 2 | 赢 / 没赢后 | `RANK_COMPARE_RESULT_AFTER` |

> 官方拼点**只有两个时机**；“亮出拼点牌后”不是拼点流程时机，它分别是牌移动的
> “移动到目标区域后”与个别技能的私有措辞。

**牌移动事件（`L16`）**

| 序 | 时机 | 标识符 | 说明 |
|---|---|---|---|
| 1 | 移动到目标区域前 | `MOVE_BEFORE` | 牌仍在原区域（= 失去前 / 获得前） |
| 2 | 移动到目标区域后 | `MOVE_AFTER` | 牌已在目标区域（= 失去后 / 获得后）；牌堆空则洗弃牌堆 |

> 移动的**来源**（官方“失去牌的原因”清单）：使用 / 打出 / 重铸 / 弃置 / 交给 /
> 拼点 / 交换 / 获得；摸牌、弃牌等应表示为牌移动的不同来源，而不是与伤害并列的
> 独立结算事件（规则文档 17.13）。

**牌状态改变（`L17`）**

| 序 | 时机 | 标识符 |
|---|---|---|
| 1 | 翻面后 | `STATE_FLIPPED` |
| 2 | 横置后 | `STATE_CHAINED` |
| 3 | 武将牌明置后 | `HERO_REVEALED` |
| 4 | 武将牌移除后 | `HERO_REMOVED` |
| 5 | 游戏牌亮出后 | `CARD_SHOWN` |

### 3.5 时机调度规则（来自规则文档 4.16）

1. **插入结算，后发先至**：插入发生的事件优先结算，即**后发生的事件先结算**。
2. **多角色同一时机**：从当前回合角色开始、按**逆时针**方向依次询问 / 触发；
   默认每名角色对同一事件只有一次机会，放弃后不可再次响应。
3. **单角色同一时机的技能优先级**：先武将技能、再装备技能、最后使用牌
   （**武将技能 > 装备技能 > 使用牌**）；多个（不同）武将技能由该角色自选顺序，
   锁定技必发。

   > **枚举注（依据票 07 §6）**：上句散文的机器形态是 `priority_class{HERO, EQUIPMENT,
   > CARD_USE}`（`IntEnum`，**值序即档序**，越小越先）。M2 的载体只有装备档，另两档是
   > 链序定义的一部分（M3 武将 / 使用牌档接入时不再改枚举）。**散文与枚举并存**：
   > 门禁既钉散文串（`tests/test_dev_docs.sh`）、又钉枚举值。
4. **“不属于任何角色的回合”的响应起点切换**：从死亡结算开始到“死亡时”期间的
   某一时机，从**该角色**开始按逆时针方向；从“死亡时”之后到死亡结算完毕期间，
   以及死亡结算完毕之后至下一个回合开始前，从**其下家**开始按逆时针方向。

> **不得作为时机值**：`防止伤害`、`扣减体力`（作为伤害行内的一步）、`回复体力时`、
> `增减体力上限时`、`增减体力上限后`、`亮出拼点牌后`、裸 `濒死` 都不是官方时机名，
> 不得出现在时机表或事件日志的时机字段中。完整黑名单与机械断言见
> `sgs.timing.FORBIDDEN_TIMING_NAMES` 与 `tests/test_timing.py`。

## 4. 事件与结算栈

### 4.1 为什么需要栈
三国杀存在大量**插入结算**：一次伤害里可能插入濒死求桃，濒死可能
插入死亡，军争的连环又会插入新的伤害；无懈可击还能层层嵌套。
必须用显式栈表达，而非递归硬写。

### 4.2 结算栈元素
| 字段 | 含义 |
|---|---|
| 事件类型 | 使用/打出/伤害/失去体力/回复/判定/拼点/濒死/死亡/摸牌/弃牌 |
| 参与角色 | 来源、目标、响应者 |
| 状态 | 未开始 / 进行中 / 等待应答 / 已结束 |
| 恢复点 | 结算完毕后要回到外层事件的哪个时机 |
| 关联数据 | 牌实例、伤害属性与点数、目标列表等 |

### 4.3 栈的规则
- 新事件**压栈并立即结算**；结算完毕**出栈**，回到外层记录的恢复点。
- 只有在“需要玩家决策”或“全部结束”时引擎才暂停。
- 终止条件：一旦满足胜负条件，**清空栈并立即结束**（规则文档 4.19）。

### 4.4 目标与多次结算
- 一张牌多目标：使用结算前“所有目标处理完一个时机再进入下个时机”；
  使用结算中“一个目标连续结算完再处理下一个”。
- 同一目标多次结算（如【方天画戟】+【流离】）：按结算次数顺序处理。

## 5. 询问 / 响应模型

### 5.1 Query 类型

`QueryKind` 现有**九类**（`src/sgs/state/protocol.py`）：票 19 §1 按决策结构定下
**七类**（M1 四类原样不动 + `RESPOND` / `SELECT_CARDS` / `SKILL_ACTIVATION`），
票 12 §Q6 追加第 8 类 `SELECT_OPTION`（【雌雄双股剑】的"二选一"，选择权在**目标**；
本轮起也用来承载【遗计】的"交给谁"——它的 `options` 本就是开放字符串闭集），
票 10 追加第 9 类 `ARRANGE`（【观星】的排列）。

| 标识符 | 场景 |
|---|---|
| `PLAY_PHASE` | 出牌阶段空闲时间点的行动选择（M1） |
| `DODGE` | 【杀】的【闪】响应（M1） |
| `PEACH` | 濒死求【桃】（M1） |
| `DISCARD` | 弃牌阶段的弃牌（M1） |
| `RESPOND` | 响应窗口：打出 / 使用一张牌或放弃（票 27） |
| `SELECT_CARDS` | 从选择面（槽位表）里挑 k 张（票 27） |
| `SKILL_ACTIVATION` | 非锁定技的"是否发动"，一次性载荷已烘进候选（票 30） |
| `SELECT_OPTION` | 选项闭集里的二选一，选择权在目标（票 12 §Q6） |

> **口径更正（依据票 19 §1 / §10 / 票 12 §Q6）**：旧表的「选择目标」「顺序选择」两类
> **M2 都不独立成询问**——目标烘进 `UseCard.targets` 候选、顺序由引擎定；两者**标注为
> M3**（`05` §1「测试金字塔」原写的"M2 多目标时再拆出独立目标询问"已被票 19 §10 取代）。旧表的
> 「颜色 / 花色 / 数量」并入 `SELECT_OPTION` / `SELECT_CARDS` 的载荷。
> M1 四类之所以不并入 `RESPOND`：回归网锁着"M1 单测原样通过"，合并会改记录形状。

### 5.2 应答者
- 人类：经接入层收集输入。
- AI：本地计算后返回。
- 脚本玩家：返回预设答案，用于测试。

三者实现**同一接口**：给定 Query 与可见信息，返回 Action 或“放弃”。

### 5.3 可见性
- 引擎生成 Query 时必须做**信息过滤**：AI 与人类只能看到合法可见信息
  （自己的手牌、公开区域、已公开身份等）。
- 引擎内部保留全知状态，**不得**通过 Query 泄露隐藏信息。

## 6. 行动（Action）模型

**"使用"与"打出"是两个独立构造子**（票 19 §2）：**使用**有目标、走 `L4` / `L5`、
占使用次数；**打出**无目标、走 `L6`、不占使用次数。用 `UseCard(targets=())` 冒充打出
会让两者在记录流里不可分，故必须分列。

| 构造子 | 场景 |
|---|---|
| `UseCard` | **使用**：指定牌实例、目标（`targets`）与参数 |
| `PlayCard` | **打出**：响应某事件而交出牌（无目标、走 `L6`、不计次数） |
| `ActivateSkill` | 发动技能：`skill_id` + 载荷（`choices` / `picks` 已在候选构造时付清） |
| `SelectCards` | 选牌：用**面内位置**引用，不携带牌面身份 |
| `SelectOption` | 在选项闭集里挑一个（【雌雄双股剑】，票 12 §Q6） |
| `DiscardCards` | 弃牌阶段 / 弃牌类效果的弃牌 |
| `Pass` | 放弃响应 |
| `EndPhase` | 结束当前阶段 |

`Action` union 的判别字段是 `kind`；`parse_action` 是行动 schema 的**唯一入口**——
未知 `kind` / 缺字段 / 多余字段一律抛 pydantic `ValidationError`，引擎归类为
`MalformedAction`。引擎对外提供“**当前合法行动集合**”，供 AI 与前端高亮，减少非法输入。

## 7. 确定性与日志

1. 唯一随机源：带种子的伪随机发生器；洗牌、判定、随机选择都走它。
2. 事件日志：每个状态变化记录“时机 + 触发者 + 效果 + 结果”，单调编号。
3. 回放 = 用相同种子重放 Action 序列，校验事件日志一致。
4. 禁止依赖：系统时间、字典/集合遍历顺序、并发调度顺序。

## 8. 规则配置（版本与存疑点）

| 配置项 | 取值 | 说明 |
|---|---|---|
| 规则版本 | standard / standard+ex / boundary | 决定内容包与技能版本 |
| 宝物槽位 | 开 / 关 | **不启用**：M6 收口确认不做宝物 / 木牛流马（ADR-006 变更块），开关无取值可开，只留枚举位 |
| 属性伤害 / 连环 | 开 / 关 | 军争篇引入 |
| 平点判定 | 双方都没赢 | 规则文档第十二章，固定 |

**原则**：存疑点必须显式配置并写入决策记录，禁止“代码里默认这样”。

> **M2 落地口径（依据票 02 / 票 11）**：原则句保留，但**结果为空清单**——M2 不建任何
> 存疑点相关的配置开关。原先的「无懈可击响应窗口」配置行（A / B 二选一的开关）**已删**：官方字面与规则
> 文档 6.16 的响应窗口条文都是**约定 B**，M2 取 B（`RESOLVE_BEFORE_EFFECT`）且不建开关
> （裁定见 `06` §4「决策记录（ADR）」 ADR-001）。规则版本 / 属性伤害 / 连环这些**合法**开关保留；
> 宝物槽位开关同样保留，但 **M6 收口确认不启用**（没有宝物牌可放，见 ADR-006 变更块）。

> **模式派生（新增裁定，依据票 13 §1）**：**模式不是配置字段**，由座位数派生——
> `player_count == 2 ⇒ 无身份局`；`4..8 ⇒ 身份局`；`3` 不在值域内，故**加载期失败**。
> 身份局的 `first_seat` **必须保持默认**（先手 = 主公座位），**不得预设**：模型校验器
> 在 `mode is IDENTITY and first_seat != 0` 时直接报错（`src/sgs/data/rule_config.py`）。
