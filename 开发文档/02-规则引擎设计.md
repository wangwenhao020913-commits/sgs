# 02 规则引擎设计

本文件描述 `rules-core` 的结构设计。**不含实现代码**，只定义概念、数据
边界与行为规则。

---

## 1. 引擎职责

引擎只做四件事：

1. **维护状态**：对局的全部事实（角色、牌、区域、标记、时机）。
2. **校验行动**：判断某个 Action 当前是否合法，不合法则给出原因。
3. **推进结算**：应用行动，按时机触发技能与效果，必要时插入子结算。
4. **抛出询问**：需要决策时生成 Query，交由参与者应答。

引擎**不做**：渲染、计时、网络、AI 策略。

---

## 2. 状态模型

### 2.1 顶层状态
| 字段 | 含义 |
|---|---|
| 对局标识 | 唯一 id、随机种子、规则版本、内容包列表 |
| 角色列表 | 全部座位（含已死亡，保留历史） |
| 牌堆 / 弃牌堆 | 有序牌实例列表 |
| 处理区 | 当前正在结算的实体牌 |
| 当前回合 | 当前回合角色、所处阶段与时机 |
| 结算栈 | 尚未结算完的嵌套事件 |
| 等待项 | 当前是否有 Query 待应答，应答者是谁 |
| 事件序号 | 单调递增，用于日志与复现 |
| 阶段标记 | 是否已结束、胜利方 |

### 2.2 角色
| 字段 | 含义 |
|---|---|
| 座位号 | 决定行动顺序与距离 |
| 身份 | 主公 / 忠臣 / 反贼 / 内奸（仅自己可见，死亡后公开） |
| 武将 | 武将 id、势力、性别 |
| 体力 | 当前体力值 / 体力上限 |
| 状态 | 存活、翻面（背面朝上）、横置（连环状态） |
| 手牌区 | 手牌实例列表 |
| 装备区 | 武器 / 防具 / +1 坐骑 / -1 坐骑 /（宝物，扩展） |
| 判定区 | 延时类锦囊实例列表（不能有两张同名） |
| 武将牌上 | 移出游戏的牌（「田」「权」「创」等） |
| 标记 | 名称 → 数量 |
| 技能状态 | 已获得 / 失效 / 已用次数 / 限定技是否已用 |

### 2.3 牌实例
| 字段 | 含义 |
|---|---|
| 实例 id | 唯一，转化与多张合成时用于追踪实体 |
| 牌名 / 类别 | 基本牌 / 锦囊牌 / 装备牌及其子类 |
| 花色 / 点数 | 判定与拼点的依据；虚拟牌可为“无” |
| 颜色 / 属性 | 红黑、火焰 / 雷电 / 普通 |
| 位置 | 牌堆 / 手牌 / 装备区 / 判定区 / 处理区 / 弃牌堆 / 移出游戏 |
| 归属 | 拥有者（判定区与移出游戏的牌不归任何人） |
| 来源 | 打出 / 使用 / 判定 / 拼点等产生方式 |

### 2.4 虚拟牌与转化
- **转化牌**：有实体来源，继承原牌花色、点数、颜色、属性，仅牌名改写。
- **虚拟牌**：无实体，标记为“无花色 / 无点数 / 无属性 / 无实体”。
- 引擎须能同时表达“牌名”与“实体来源”，供【武圣】【奇袭】【急救】
  【激将】【护驾】等使用（对应规则文档第十六章）。

## 3. 时机系统（引擎核心）

把规则文档 3.9 / 17.10 / 4.14 的时机表编码为**枚举**，技能注册到时机上。
时机表分四组：

### 3.1 回合与阶段时机
| 时机 | 说明 |
|---|---|
| 回合开始前 | 背面朝上则先翻面并跳过整个回合 |
| 回合开始时 | “回合内”从此开始 |
| 各阶段开始时 / 阶段 / 阶段结束时 | 准备、判定、摸牌、出牌、弃牌、结束 |
| 各相邻阶段之间 | 如“准备阶段与判定阶段间” |
| 回合结束时 / 回合结束后 | “回合外”从回合结束后开始 |

### 3.2 使用结算前（六个）
选择目标时 → 使用牌时 → 指定目标时 → 成为目标时 → 指定目标后 →
成为目标后。

### 3.3 使用结算中（五个，逐目标）
使用结算开始时（有效性检测）→ 生效前（响应/抵消）→ 生效时 →
生效后（执行效果）→ 使用结算结束时。

### 3.4 其他事件时机
| 事件 | 时机 |
|---|---|
| 伤害 | 防止伤害 → 造成伤害时 → 扣减体力 → 濒死 → 造成伤害后 → 受到伤害后 |
| 失去体力 | 失去体力时 / 后 |
| 回复体力 | 回复体力时 / 后 |
| 体力上限 | 增减体力上限时 / 后 |
| 判定 | 判定时 → 判定牌生效前 → 判定牌生效后 |
| 拼点 | 进行拼点时 → 亮出拼点牌后 → 赢/没赢后 |
| 死亡 | 死亡时 → 死亡后（奖惩与胜负判定） |

### 3.5 时机调度的两条规则（来自规则文档 4.16）
1. 同一角色同一时点多个技能：**由该角色自选顺序**，锁定技必发。
2. 多角色同一时点响应：**从当前回合角色起、逆时针**依次询问，
   默认每人一次机会，放弃即不可再响应。

## 4. 事件与结算栈

### 4.1 为什么需要栈
三国杀存在大量**插入结算**：一次伤害里可能插入濒死求桃，濒死可能
插入死亡，军争的连环又会插入新的伤害；无懈可击还能层层嵌套。
必须用显式栈表达，而非递归硬写。

### 4.2 结算栈元素
| 字段 | 含义 |
|---|---|
| 事件类型 | 使用/打出/伤害/失去体力/回复/判定/拼点/濒死/死亡/摸牌/弃牌 |
| 参与角色 | 来源、目标、响应者 |
| 状态 | 未开始 / 进行中 / 等待应答 / 已结束 |
| 恢复点 | 结算完毕后要回到外层事件的哪个时机 |
| 关联数据 | 牌实例、伤害属性与点数、目标列表等 |

### 4.3 栈的规则
- 新事件**压栈并立即结算**；结算完毕**出栈**，回到外层记录的恢复点。
- 只有在“需要玩家决策”或“全部结束”时引擎才暂停。
- 终止条件：一旦满足胜负条件，**清空栈并立即结束**（规则文档 4.19）。

### 4.4 目标与多次结算
- 一张牌多目标：使用结算前“所有目标处理完一个时机再进入下个时机”；
  使用结算中“一个目标连续结算完再处理下一个”。
- 同一目标多次结算（如【方天画戟】+【流离】）：按结算次数顺序处理。

## 5. 询问 / 响应模型

### 5.1 Query 类型
| 类型 | 场景 |
|---|---|
| 选择目标 | 使用牌或技能时选合法目标 |
| 选择牌 | 弃牌、交牌、改判、拼点 |
| 是否发动技能 | 非锁定技的发动确认（含选 Modi / 选项） |
| 打出 / 使用响应 | 打出【闪】【杀】，使用【无懈可击】 |
| 顺序选择 | 同一时点多技能 / 多目标的顺序 |
| 颜色 / 花色 / 数量 | 技能参数选择 |

### 5.2 应答者
- 人类：经接入层收集输入。
- AI：本地计算后返回。
- 脚本玩家：返回预设答案，用于测试。

三者实现**同一接口**：给定 Query 与可见信息，返回 Action 或“放弃”。

### 5.3 可见性
- 引擎生成 Query 时必须做**信息过滤**：AI 与人类只能看到合法可见信息
  （自己的手牌、公开区域、已公开身份等）。
- 引擎内部保留全知状态，**不得**通过 Query 泄露隐藏信息。

---

## 6. 行动（Action）模型

| Action | 说明 |
|---|---|
| 使用牌 | 指定牌实例、牌名、目标、参数 |
| 打出牌 | 响应某事件而交出牌 |
| 发动技能 | 技能 id + 参数 |
| 放弃 / 结束阶段 | 进入下一阶段或放弃响应 |
| 结算阶段推进 | 由引擎在无询问时自动进行 |

引擎对外提供“**当前合法行动集合**”，供 AI 与前端高亮，减少非法输入。

---

## 7. 确定性与日志

1. 唯一随机源：带种子的伪随机发生器；洗牌、判定、随机选择都走它。
2. 事件日志：每个状态变化记录“时机 + 触发者 + 效果 + 结果”，单调编号。
3. 回放 = 用相同种子重放 Action 序列，校验事件日志一致。
4. 禁止依赖：系统时间、字典/集合遍历顺序、并发调度顺序。

---

## 8. 规则配置（版本与存疑点）

| 配置项 | 取值 | 说明 |
|---|---|---|
| 规则版本 | standard / standard+ex / boundary | 决定内容包与技能版本 |
| 无懈可击窗口 | A（使用生效前）/ B（判定阶段） | 见规则文档 6.16 的存疑点 |
| 宝物槽位 | 开 / 关 | 界限突破引入 |
| 属性伤害 / 连环 | 开 / 关 | 军争篇引入 |
| 平点判定 | 双方都没赢 | 规则文档第十二章，固定 |

**原则**：存疑点必须显式配置并写入决策记录，禁止“代码里默认这样”。
